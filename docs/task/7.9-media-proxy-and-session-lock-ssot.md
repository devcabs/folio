## 🎯 Purpose & Scope

Eliminate media proxy SVG fallbacks, client image loader fallback URLs (`drive.google.com/thumbnail`), Supabase `dev_mode_session`, and browser `localStorage`/`sessionStorage` coordinator lock fallbacks across `src/edge/handlers/mediaHandler.ts`, `src/edge/handlers/lockHandler.ts`, `src/hooks/useImageLoader.ts`, `src/components/source/SourceCard.tsx`, `src/components/source/SourceLightbox.tsx`, `src/services/devLockService.ts`, and `src/context/DeveloperModeContext.tsx`:
1. **Fail-Stop Edge Media Proxy (`src/edge/handlers/mediaHandler.ts`)**:
   - When upstream Google Drive returns 403, 404, or any non-2xx status, return an explicit error response (`status: driveResponse.status`, `Content-Type: application/json`) instead of synthesizing a `200`/`403`/`404` `image/svg+xml` placeholder (`renderPlaceholderSvg`).
2. **Eliminate Client Image Fallback to Direct Google Drive Thumbnail (`src/hooks/useImageLoader.ts`, `src/components/source/SourceCard.tsx`, `src/components/source/SourceLightbox.tsx`, `src/components/source/SourceImage.tsx`)**:
   - Remove `fallbackSrc` (`https://drive.google.com/thumbnail?id=${driveFileId}&sz=w1600`) from `SourceCard.tsx`, `SourceLightbox.tsx`, `SourceImage.tsx`, and `useImageLoader.ts`.
   - All Drive images must load exclusively through the single authoritative Edge Media Proxy (`/api/media/drive/:fileId?w=...`). If the edge proxy returns an error, `useImageLoader` transitions immediately to `status = 'error'`, rendering the tokenized error fallback UI in `SourceImage` with a Retry button.
3. **Cloudflare KV Coordinator Session Lock & PIN Rate-Limit (`src/edge/handlers/lockHandler.ts`, `src/edge/router.ts`, `src/services/devLockService.ts`, `src/context/DeveloperModeContext.tsx`)**:
   - Eliminate Supabase `dev_mode_session`, `localStorage` (`_dev_lock`), and `sessionStorage` (`_dev_session_id`) from `src/services/devLockService.ts`.
   - Implement `src/edge/handlers/lockHandler.ts` and register `/api/lock` in `src/edge/router.ts` (and `functions/api/lock.ts`), storing coordinator lock state in Cloudflare KV under `lock:coordinator` (`{ sessionId, lockedAt, heartbeatAt, expiresAt }`) and PIN rate-limit state under `lock:pin_ratelimit` (`{ failedAttempts, lockoutUntil }`):
     - `GET /api/lock`: Reads `lock:coordinator` and `lock:pin_ratelimit` from Cloudflare KV. Returns `{ isLocked, canAcquire, holderSessionId, expiresAt, lockoutUntil }`. Fails stop with HTTP 503 if `!kv`.
     - `POST /api/lock`: Verifies `lock:pin_ratelimit` (returning HTTP 429 if locked out), verifies the coordinator's PIN hash or session claim, checks `lock:coordinator` (returning HTTP 409 if an active non-expired lock is held by another `sessionId`), and writes `lock:coordinator` to Cloudflare KV with a 60-second TTL (`expirationTtl: 60`).
     - `PATCH /api/lock`: Renews the heartbeat on `lock:coordinator` in Cloudflare KV if and only if the current holder matches `sessionId` (returning HTTP 409/404 if lost or expired).
     - `DELETE /api/lock`: Releases `lock:coordinator` in Cloudflare KV (`kv.delete('lock:coordinator')`) if held by `sessionId`.
   - Enforce **Strict Fail-Stop on Lock Operations**: If `/api/lock` returns non-2xx or throws a network error during `checkDevLockStatus()`, `acquireDevLock()`, or `renewDevLockHeartbeat()`, fail stop immediately (`canAcquire: false` / `success: false` / `false`), blocking Dev Mode entry or evicting the active session—never granting a browser-local fallback lock.

## 🔍 Forensic Audit Findings Addressed

1. **[V9.1] Edge Media Proxy Synthetic SVG Fallback & Client `useImageLoader` Direct Drive Fallback**
   - **Locations**: [mediaHandler.ts](file:///Users/francisdave/Documents/folio/src/edge/handlers/mediaHandler.ts#L14-L40), [mediaHandler.ts](file:///Users/francisdave/Documents/folio/src/edge/handlers/mediaHandler.ts#L138-L141), [useImageLoader.ts](file:///Users/francisdave/Documents/folio/src/hooks/useImageLoader.ts#L47-L55), [SourceCard.tsx](file:///Users/francisdave/Documents/folio/src/components/source/SourceCard.tsx#L117-L119), [SourceLightbox.tsx](file:///Users/francisdave/Documents/folio/src/components/source/SourceLightbox.tsx#L236-L238)
   - **Conflicting Sources / Fallback Chain**:
     - Edge: `caches.default` → Google Drive thumbnail → `renderPlaceholderSvg()` (`X-Engine-Media-Source: UPSTREAM_FALLBACK_SVG`).
     - Client: `/api/media/drive/${driveFileId}?w=...` → on `img.onerror`, `useImageLoader` switches `activeSrc` to `fallbackSrc` (`https://drive.google.com/thumbnail?id=${driveFileId}&sz=w1600`).
   - **Why It Violates SSOT**: Fetches images from two competing sources (Edge Media Proxy and direct Google Drive) and masks upstream 403/404 errors with a synthetic SVG image.

2. **[V9.2 (Part B)] Coordinator Session Lock Split Across Supabase, `localStorage`, and `sessionStorage` with Offline Local Lock Grant**
   - **Locations**: [devLockService.ts](file:///Users/francisdave/Documents/folio/src/services/devLockService.ts#L61-L105), [devLockService.ts](file:///Users/francisdave/Documents/folio/src/services/devLockService.ts#L138-L510), [DeveloperModeContext.tsx](file:///Users/francisdave/Documents/folio/src/context/DeveloperModeContext.tsx#L532-L556)
   - **Conflicting Sources / Fallback Chain**: Session ID: `sessionStorage` → `inMemorySessionId`. Lock: Supabase `dev_mode_session` ↔ `localStorage` (`_dev_lock`). On Supabase 404, HTTP error, or network exception, `devLockService` writes the lock to `localStorage` and returns `success: true`.
   - **Why It Violates SSOT**: Uses Supabase, `localStorage`, and `sessionStorage`, and silently grants a browser-local lock when the remote store fails—allowing multiple coordinators on different devices to enter Dev Mode simultaneously.
