## 🎯 Purpose & Scope

Consolidate Folio Engine's multi-step, browser-orchestrated write and publish pipeline into an **atomic, single-pipeline execution**.

Currently, publishing a revision requires the user's browser to independently coordinate five separate storage operations across multiple networks:
1. Writing 5 separate canvas documents to browser `localStorage`.
2. Writing flat key-value overrides to `localStorage`.
3. Making an unauthenticated or anon-key `POST` to Supabase `engine_history`.
4. Making a second `PATCH` request to Supabase to demote previous active snapshots.
5. Calling Cloudflare's KV REST API (`api.cloudflare.com/.../bulk`) directly from the browser, which requires exposing `CLOUDFLARE_API_TOKEN` to client-side code!

Furthermore, during draft editing, canvas modifications are saved redundantly: once in the Canvas AST JSON, and again parsed as flat keys in `ContentDB`.

This task:
1. Establishes the **Canvas AST as the sole authority** for all canvas elements, eliminating double-storage in `ContentDB`.
2. Replaces the browser's distributed multi-hop publish flow with an atomic server-side edge function (`POST /api/publish`) that validates the session, writes to Supabase, and compiles/deploys to Edge KV within a single server-side lifecycle.

## 🔍 Problem Statement

### 1. Dual-Storage Redundancy
In `src/components/dev/UniversalEditModal.tsx` (lines 485–514) and `DocumentCanvas.tsx` (lines 480–520):
- When an author edits a section title or photo caption, `UniversalEditModal` calls `setContent(pointId, value, true)`.
- At the same time, `DocumentCanvas` calls `updateItem` on the AST.
- On startup, `migrateCanvasOverridesIntoAst` attempts to fold flat `ContentDB` strings back into the AST.
- This creates race conditions, wasted CPU cycles, and dual points of failure.

### 2. Client-Orchestrated Split-Brain Risk
In `src/services/historyService.ts` (`publishNewSnapshot`):
- If the network drops between Supabase `POST` and Cloudflare KV `PUT`, Supabase records the snapshot as active, but Cloudflare Edge KV serves stale data.
- The client browser is responsible for retrying, recovering, and managing Cloudflare API credentials.

### 3. Security Vulnerability
- Directly dispatching to `https://api.cloudflare.com/client/v4/accounts/.../bulk` from the client necessitates storing `CLOUDFLARE_API_TOKEN` in client-accessible environment variables, violating security guidelines.

## 🛠️ Step-by-Step Implementation Instructions

### Step 1: Create Edge Publish Endpoint `functions/api/publish.ts`

```ts
import type { PagesFunctionEventContext } from '../../src/types/edge';
import type { PublishedSnapshot } from '../../src/types/history';

export async function onRequestPost(context: PagesFunctionEventContext<any>): Promise<Response> {
  const { request, env } = context;

  try {
    const body = await request.json() as { snapshot: PublishedSnapshot };
    const { snapshot } = body;

    if (!snapshot || !snapshot.id || !snapshot.canvases) {
      return new Response(JSON.stringify({ error: 'Malformed snapshot payload' }), {
        status: 400,
        headers: { 'Content-Type': 'application/json' },
      });
    }

    // 1. Persist to Supabase if configured in env
    const supabaseUrl = env.VITE_SUPABASE_URL || env.SUPABASE_URL;
    const supabaseKey = env.SUPABASE_SERVICE_ROLE_KEY || env.VITE_SUPABASE_ANON_KEY;

    if (supabaseUrl && supabaseKey) {
      const payload = {
        id: snapshot.id,
        schema_version: snapshot.schemaVersion,
        title: snapshot.title,
        description: snapshot.description,
        snapshot_data: {
          canvases: snapshot.canvases,
          contentOverrides: snapshot.contentOverrides,
        },
        summary: snapshot.summary,
        is_active: true,
        author_session_id: snapshot.authorSessionId,
        created_at: snapshot.createdAt,
      };

      const res = await fetch(`${supabaseUrl}/rest/v1/engine_history`, {
        method: 'POST',
        headers: {
          apikey: supabaseKey,
          Authorization: `Bearer ${supabaseKey}`,
          'Content-Type': 'application/json',
          Prefer: 'return=representation',
        },
        body: JSON.stringify(payload),
      });

      if (res.ok) {
        // Demote previous active
        await fetch(`${supabaseUrl}/rest/v1/engine_history?is_active=eq.true&id=neq.${snapshot.id}`, {
          method: 'PATCH',
          headers: {
            apikey: supabaseKey,
            Authorization: `Bearer ${supabaseKey}`,
            'Content-Type': 'application/json',
          },
          body: JSON.stringify({ is_active: false }),
        });
      }
    }

    // 2. Pre-bake directly into KV using edge binding (zero external REST API calls)
    if (env.KV_ENGINE_PUBLIC) {
      for (const [nodeId, canvas] of Object.entries(snapshot.canvases)) {
        await env.KV_ENGINE_PUBLIC.put(`node:${nodeId}`, JSON.stringify({
          nodeId,
          snapshotId: snapshot.id,
          version: canvas.version || 2,
          updatedAt: snapshot.createdAt,
          canvas,
          chartDatasets: {},
        }));
      }

      await env.KV_ENGINE_PUBLIC.put('portal:manifest', JSON.stringify({
        activeSnapshotId: snapshot.id,
        publishedAt: snapshot.createdAt,
        nodeIds: Object.keys(snapshot.canvases),
        schemaVersion: snapshot.schemaVersion,
      }));
    }

    return new Response(JSON.stringify({
      success: true,
      snapshotId: snapshot.id,
      publishedAt: snapshot.createdAt,
    }), {
      status: 200,
      headers: { 'Content-Type': 'application/json' },
    });
  } catch (err: unknown) {
    const msg = err instanceof Error ? err.message : 'Unknown publish failure';
    return new Response(JSON.stringify({ error: msg }), {
      status: 500,
      headers: { 'Content-Type': 'application/json' },
    });
  }
}
```
