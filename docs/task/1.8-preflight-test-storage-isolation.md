## 🎯 Purpose & Scope

Eliminate order-dependent flaky tests by enforcing that all watermark and migration state in tests uses injected in-memory storage — never the shared jsdom `localStorage` shim. Establish the structural test conventions (`beforeEach` isolation, explicit adapter injection) that all current and future migration tests must follow, so that tests pass identically regardless of execution order or parallelism.

---

## 🔍 Problem Statement

Task 1.15's `tests/migration.test.ts` will test watermark persistence using `localStorage`. Vitest's jsdom environment provides a `localStorage` shim that PERSISTS across all tests within a file. If test A sets the watermark to `'0.1.3'` and test B expects `'0.0.0'` (baseline), test B will fail only when run after test A. This creates order-dependent flaky tests that pass in isolation but fail in CI. The fix requires the storage layer to be injected, not global.

2. **`tests/migration.test.ts`** *(Pre-wire structure for 1.15)*
   - Establish the structural test conventions all migration tests must follow:
     - Every `describe` block that touches watermark state MUST declare isolated storage:
       ```ts
       import { createInMemoryAdapter, StorageAdapter } from '../src/utils/storageAdapter';

       describe('watermark resolution', () => {
         let storage: StorageAdapter;
         beforeEach(() => {
           storage = createInMemoryAdapter();
         });
         // ... tests pass `storage` explicitly
       });
       ```
     - ALL storage interactions go through the injected `storage` adapter — zero direct `localStorage`, `window.localStorage`, or `globalThis.localStorage` calls anywhere in test files.
     - Function calls that accept storage must receive the injected adapter:
       ```ts
       getContentVersionWatermark(config, storage)
       setContentVersionWatermark(version, storage)
       getPendingMigrations(watermark, storage)
       resolveContentWatermark(configVersion, storage)
       updateWatermark(newVersion, storage)
       ```
   - Add a mandatory isolation test:
     ```ts
     it('storage adapter is isolated between test cases', () => {
       const a = createInMemoryAdapter();
       const b = createInMemoryAdapter();
       a.setItem('key', 'value-a');
       expect(b.getItem('key')).toBeNull(); // No shared state
     });
     ```
   - Stub out the describe blocks for tasks 1.10–1.15 test coverage (empty `it.todo(...)` blocks) so the test file structure is established now.
