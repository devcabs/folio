## 🎯 Purpose & Scope

Enforce strict release discipline so that no version of `@devcabs/folio-engine` can ever be published to npm without documenting breaking changes, migration steps, and content requirements in `src/migrations/ledger.ts`. Automatically compile `CHANGELOG.md` directly from the ledger during builds and releases.

---

## 📄 Key Files to Create / Modify

1. **`scripts/generate-changelog.ts`** *(New)*
   - Imports `FOLIO_MIGRATION_LEDGER` from `src/migrations/ledger.ts`.
   - Generates a GitHub-flavored Markdown `CHANGELOG.md` in repository root.
   - Formats each release:
     - Version, Date, and Headline Summary.
     - Breaking Changes list.
     - Code Migrations & Examples.
     - Required Content Changes & Schemas.

2. **`scripts/deploy.ts`** *(Modify)*
   - Add **Pre-Release Ledger Verification Gate** before bumping npm version:
     - Calculates the target version (e.g. if current is `0.1.3` and bumping `patch`, target is `0.1.4`).
     - Reads `src/migrations/ledger.ts`.
     - Validates that an entry for the target version exists and has non-empty fields.
     - If missing:
       - Fails deployment immediately (`process.exit(1)`).
       - Prints:
         ```
         ❌ DEPLOY BLOCKED: Missing migration ledger entry for v0.1.4!
         Please add a release entry in src/migrations/ledger.ts detailing:
           - breakingChanges
           - codeActions
           - contentChanges
         before running deploy.
         ```
     - If valid:
       - Compiles updated `CHANGELOG.md`.
       - Stages `CHANGELOG.md` and proceeds with version bump, build, publish, and tag push.

3. **`package.json`** *(Modify)*
   - Add script: `"changelog": "tsx scripts/generate-changelog.ts"`.

---

## 🔍 Verification Criteria

- [x] `npm run changelog` generates a formatted `CHANGELOG.md`.
- [x] Attempting to deploy with an untracked version bump causes `deploy.ts` to abort with a clear error.
- [x] Attempting to deploy with a valid ledger entry passes the gate.
