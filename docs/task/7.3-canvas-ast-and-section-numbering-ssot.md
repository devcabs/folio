## 🎯 Purpose & Scope

Make `NodeCanvasDocument` a **100% self-contained Document AST** stored directly in Cloudflare KV (`node:${nodeId}` in Public Mode, `draft:workspace.canvases[nodeId]` in Dev Mode, and `history:snapshot:${id}.canvases[nodeId]` in History):
1. **Self-Contained `NodeCanvasDocument` AST Contract (`src/types/canvas.ts`, `src/types/edge.ts`)**:
   - Embed chart configurations and pre-baked datasets directly inside `ChartElement`:
     ```ts
     export interface ChartElement extends CanvasElementBase {
       type: 'chart';
       chartId: string;
       title: string;
       subtitle?: string;
       config?: SheetChartConfig;
       dataset?: ChartDataset;
     }
     ```
   - Embed evidence gallery folder metadata and synced photos directly inside `GalleryElement`:
     ```ts
     export interface GalleryElement extends CanvasElementBase {
       type: 'gallery';
       pointId: string;
       title?: string;
       subtitle?: string;
       driveUrl?: string;
       description?: string;
       lastVerified?: string;
       syncedPhotos?: SyncedSourceItem[];
     }
     ```
   - Remove sidecar `chartDatasets` and `sourceMetadata` maps from `PublicNodePayload`, `PublishedSnapshot`, and `UnifiedPortalSnapshot` so every node's `NodeCanvasDocument` is completely self-contained and atomic across drafts, publishing, and rollbacks.
2. **Eliminate `ContentDB` Shadowing of Canvas Titles & Numbering**:
   - Stop `SectionTitle.tsx`, `CanvasSection.tsx`, `CanvasSubsection.tsx`, `use-dynamic-section-numbers.ts`, and `UniversalEditModal.tsx` from reading or writing section/subsection titles or `.isNumbered` flags in `ContentDB`.
3. **Purge `localStorage`, Module-Level `inMemoryDraftCanvases`, Legacy AST Folding & Supabase `node_canvas` (`src/services/canvasLayoutService.ts`)**:
   - Remove `migrateLegacyStorageKeys()`, `foldCanvasOverridesIntoDocument()`, `migrateCanvasOverridesIntoAst()`, `getLiveNodeCanvas()`, `saveLiveNodeCanvas()`, and `deployNodeCanvasToCloud()`.
   - Remove `localStorage` reads/writes and module-level `inMemoryDraftCanvases` shadow caches; `canvasLayoutService.ts` becomes a set of pure, stateless AST transformation functions (`insertSection`, `updateElement`, `removeElement`, `moveElement`, etc.) while `useDocumentCanvas.ts` reads and writes the AST directly to Cloudflare KV (`GET /api/public/node/:nodeId` in Public Mode, `GET / PUT /api/draft` in Dev Mode).
4. **Purge `useDocumentCanvas` Fallback & Sidecar Cache Copying (`src/hooks/useDocumentCanvas.ts`)**:
   - Remove the fallback in `useDocumentCanvas` that substitutes `documentRef.current` or `createDefaultCanvasDocument` when a KV read fails.
   - Remove side-effect copying of `edgeData.chartDatasets` into `chartSourceService` and `edgeData.sourceMetadata` into `sourceService`.
5. **Unify Delete Undo State (`src/components/canvas/DocumentCanvas.tsx`)**:
   - Remove duplicate `undoBackup` state in `DocumentCanvas.tsx`; wire the deletion Toast's "Undo" action directly to `useUndoRedo().undo()`.

## 🔍 Forensic Audit Findings Addressed

1. **[V3.1] Dual Representation of Canvas Titles & `isNumbered` in `ContentDB` and Canvas AST**
   - **Locations**: [canvasLayoutService.ts](file:///Users/francisdave/Documents/folio/src/services/canvasLayoutService.ts#L94-L325), [SectionTitle.tsx](file:///Users/francisdave/Documents/folio/src/components/ui/SectionTitle.tsx#L65-L108), [CanvasSection.tsx](file:///Users/francisdave/Documents/folio/src/components/canvas/CanvasSection.tsx#L42-L76), [CanvasSubsection.tsx](file:///Users/francisdave/Documents/folio/src/components/canvas/CanvasSubsection.tsx#L36-L53), [use-dynamic-section-numbers.ts](file:///Users/francisdave/Documents/folio/src/hooks/use-dynamic-section-numbers.ts#L91-L108), [UniversalEditModal.tsx](file:///Users/francisdave/Documents/folio/src/components/dev/UniversalEditModal.tsx#L331-L342)
   - **Conflicting Sources / Fallback Chain**: `ContentDB` (`${titlePointId}` and `${titlePointId}.isNumbered`) ↔ `NodeCanvasDocument` AST (`section.title`, `section.isNumbered`, `subsection.title`).
   - **Why It Violates SSOT**: Section titles, subsection titles, and section numbering are read from both `ContentDB` and the `NodeCanvasDocument` AST.

2. **[V3.2] Shadow `localStorage` & Module-Level Canvas Stores**
   - **Locations**: [canvasLayoutService.ts](file:///Users/francisdave/Documents/folio/src/services/canvasLayoutService.ts#L867-L990)
   - **Conflicting Sources / Fallback Chain**: `inMemoryDraftCanvases` / `localStorage` (`_live_canvas_${nodeId}`, `_draft_canvas_${nodeId}`) → `createDefaultCanvasDocument(nodeId)`
   - **Why It Violates SSOT**: Persists shadow copies of canvases in `localStorage` and module-level memory alongside Cloudflare KV and silently returns an empty default document when storage is missing.

3. **[V3.3] Separate Supabase `node_canvas` / `pillar_canvas` Deploy with Fake Offline Success**
   - **Locations**: [canvasLayoutService.ts](file:///Users/francisdave/Documents/folio/src/services/canvasLayoutService.ts#L1116-L1169)
   - **Conflicting Sources / Fallback Chain**: `getLiveNodeCanvas(nodeId)` (`localStorage`) → POST `/rest/v1/node_canvas` (table check `'pillar_canvas'`) → `{ success: true }` when `!config`.
   - **Why It Violates SSOT**: Writes canvas state to a Supabase table (`node_canvas`) outside Cloudflare KV and fakes `{ success: true }` when offline.

4. **[V3.4] `useDocumentCanvas` Dev-Mode Fallback & Sidecar Cache Splitting**
   - **Locations**: [useDocumentCanvas.ts](file:///Users/francisdave/Documents/folio/src/hooks/useDocumentCanvas.ts#L127-L145), [useDocumentCanvas.ts](file:///Users/francisdave/Documents/folio/src/hooks/useDocumentCanvas.ts#L209-L269)
   - **Conflicting Sources / Fallback Chain**:
     - Dev-mode toggle (L131–139): `getNodeCanvas(nodeId, true)` → `documentRef.current` → `createDefaultCanvasDocument`.
     - Public hydration (L209–254): Copies `edgeData.chartDatasets` into `chartSourceService` and `edgeData.sourceMetadata` into `sourceService`.
   - **Why It Violates SSOT**: Substitutes live component state when draft is empty, and splits charts and galleries out of the Canvas AST into sidecar module caches.

5. **[V3.5] Duplicate Delete Undo State in `DocumentCanvas.tsx` vs. `UndoRedoContext`**
   - **Locations**: [DocumentCanvas.tsx](file:///Users/francisdave/Documents/folio/src/components/canvas/DocumentCanvas.tsx#L172), [DocumentCanvas.tsx](file:///Users/francisdave/Documents/folio/src/components/canvas/DocumentCanvas.tsx#L186-L243), [useDocumentCanvas.ts](file:///Users/francisdave/Documents/folio/src/hooks/useDocumentCanvas.ts#L336-L363)
   - **Conflicting Sources / Fallback Chain**: `DocumentCanvas` local `undoBackup` state vs. `UndoRedoContext` stack.
   - **Why It Violates SSOT**: Stores deletion undo state in two places; triggering toast undo bypasses `UndoRedoContext`.

## 🏛️ Karpathy Heuristics & Superpowers TDD

1. **Think Before Coding**:
   - Embedding `config` and `dataset` directly on `ChartElement` and `syncedPhotos` directly on `GalleryElement` makes `NodeCanvasDocument` 100% self-contained. When a coordinator edits a chart or syncs a Drive folder in Dev Mode, `useDocumentCanvas` updates the `ChartElement` or `GalleryElement` inside `NodeCanvasDocument` and persists the updated AST directly to KV `draft:workspace` via `PUT /api/draft`.
   - When published via `POST /api/publish`, the exact self-contained `NodeCanvasDocument` is written to `node:${nodeId}` and `history:snapshot:${id}` in Cloudflare KV—making drafts, publishing, and historical rollbacks completely atomic!
2. **Test-Driven Development (Superpowers)**:
   - Write tests in `tests/ssot-canvas-ast.test.ts` verifying:
     - `ChartElement` and `GalleryElement` serialize and validate their embedded `config`, `dataset`, and `syncedPhotos` inside `NodeCanvasDocumentSchema`.
     - `useDynamicCanvasSectionNumbers` computes numbers purely from `SectionElement.isNumbered` and ignores `ContentDB`.
     - `useDocumentCanvas` reads Public Mode ASTs from `GET /api/public/node/:nodeId`, reads/writes Dev Mode ASTs directly via `GET / PUT /api/draft`, and fails stop (setting `fetchError`) on any KV read/write error.
     - Clicking "Undo" on the deletion toast in `DocumentCanvas` pops the action from `useUndoRedo()`.

2. In `src/components/canvas/DocumentCanvas.tsx`, remove `undoBackup` state and wire `handleUndoDelete` directly to `useUndoRedo().undo()`.
