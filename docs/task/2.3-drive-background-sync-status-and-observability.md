## 🎯 Purpose & Scope

Eliminate silent cloud write failures in `sourceService.ts` and establish a clear distinction between **manual sync feedback** (immediate toast notifications) and **background sync feedback** (silent, registered to a status event log without popup toasts).

---

## 🔍 Problem Statement

In `src/services/sourceService.ts`:
1. `upsertLiveSourceSource(payload, token)` attempts to persist the updated photo manifest to Supabase `engine_sources` (lines 351–364).
2. If Supabase rejects the write (e.g., HTTP 401/403 RLS violation, network disconnect, or schema mismatch), the error is completely swallowed:
   ```ts
   } catch {
     // Local snapshot remains intact even if network fails
   }
   ```
3. The function returns `updatedSource` with zero indication that the cloud database was not updated!
4. Furthermore, in `src/hooks/useDrivePhotoSync.ts`, background sync timers and manual button clicks share the same state transitions. If an automatic background sync triggers an error toast, it interrupts the coordinator unexpectedly.

### Step 2: Add Event Helper `notifySyncStatus`

In `src/services/sourceService.ts`:
```ts
export const EVENT_SOURCE_SYNC_STATUS = 'engine-source-sync-status';

function notifySyncStatus(pointId: string, cloudSynced: boolean, error?: string): void {
  if (typeof window === 'undefined') return;
  try {
    window.dispatchEvent(
      new CustomEvent(EVENT_SOURCE_SYNC_STATUS, {
        detail: { pointId, cloudSynced, error, timestamp: new Date().toISOString() },
      })
    );
  } catch {
    // Non-browser context
  }
}
```
