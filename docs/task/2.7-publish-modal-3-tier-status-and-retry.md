## 🎯 Purpose & Scope

Provide immediate, transparent visual feedback on publishing progress across all three deployment tiers (`Local Snapshot ✔`, `Supabase Cloud ✔`, `Cloudflare Edge ✔`). If the Edge deployment fails while the snapshot was successfully committed to Supabase, the Publish modal must **remain open** and present a dedicated **"Retry Edge Deploy"** button, allowing the coordinator to re-dispatch the payload to Cloudflare KV without re-bundling or duplicating snapshots.

---

## 🔍 Problem Statement

In `src/components/dev/DevPublishModal.tsx`:
1. When publishing starts, a generic loading spinner is displayed.
2. Upon completion of `publishNewSnapshot()`, the modal immediately closes and displays a generic toast.
3. If the Edge KV pre-bake fails, the coordinator has zero visibility and no retry affordance. The only recourse is to make another dummy edit and re-publish, which clutters the changelog and snapshot history with duplicate entries.

## 🛠️ Step-by-Step Implementation Instructions

### Step 1: Add State & Retry Handler in `DevPublishModal.tsx`

```ts
import { compileAndDeployToEdgeKV } from '../../services/edgePreBakeService';
import type { PublishedSnapshot } from '../../types/history';

// Component state:
const [publishStep, setPublishStep] = useState<'idle' | 'publishing' | 'edge_failed' | 'complete'>('idle');
const [tierStatus, setTierStatus] = useState({ local: false, cloud: false, edge: false });
const [tierErrors, setTierErrors] = useState<{ cloud?: string; edge?: string }>({});
const activePublishedSnapshotRef = useRef<PublishedSnapshot | null>(null);

// In handleConfirmPublish:
setPublishStep('publishing');
const result = await publishNewSnapshot(description, title);
activePublishedSnapshotRef.current = result.snapshot;

setTierStatus({
  local: result.localSaved,
  cloud: result.cloudSynced,
  edge: result.edgeDeployed,
});
setTierErrors({ cloud: result.cloudError, edge: result.edgeError });

if (!result.edgeDeployed) {
  setPublishStep('edge_failed');
  // DO NOT close modal! Allow user to inspect and retry
} else {
  setPublishStep('complete');
  showToast('Published to all channels successfully.', 'success');
  onClose();
}

// Retry handler:
const handleRetryEdgeDeploy = async () => {
  if (!activePublishedSnapshotRef.current) return;
  setPublishStep('publishing');
  try {
    const retryRes = await compileAndDeployToEdgeKV(activePublishedSnapshotRef.current);
    if (retryRes.success) {
      setTierStatus(prev => ({ ...prev, edge: true }));
      setTierErrors(prev => ({ ...prev, edge: undefined }));
      setPublishStep('complete');
      showToast('Edge deployment succeeded on retry.', 'success');
      onClose();
    } else {
      setTierStatus(prev => ({ ...prev, edge: false }));
      setTierErrors(prev => ({ ...prev, edge: retryRes.deployResult?.error || 'Edge deploy failed' }));
      setPublishStep('edge_failed');
    }
  } catch (err: unknown) {
    setTierStatus(prev => ({ ...prev, edge: false }));
    setTierErrors(prev => ({ ...prev, edge: err instanceof Error ? err.message : 'Network error' }));
    setPublishStep('edge_failed');
  }
};
```

### Step 2: Render 3-Tier Status Checklist in Modal

When `publishStep === 'edge_failed'` or `'publishing'`:
Render a checklist:
- `Local Snapshot`: `✔ Saved`
- `Supabase Cloud`: `tierStatus.cloud ? '✔ Synced' : '⚠ Failed: ' + tierErrors.cloud`
- `Cloudflare KV Edge`: `tierStatus.edge ? '✔ Deployed' : '❌ Failed: ' + tierErrors.edge`

If `publishStep === 'edge_failed'`:
Render actions:
- Secondary button: `Close Anyway` (calls `onClose()`)
- Primary button: `Retry Edge Deploy` (calls `handleRetryEdgeDeploy()`)

## 🚫 Strict Prohibitions

- Do NOT auto-close the modal when `result.edgeDeployed === false`.

- Do NOT use hardcoded colors (`#10b981`, `#ef4444`, etc.) in JSX or CSS modules.
