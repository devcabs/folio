## 🎯 Purpose & Scope

Eliminate all browser storage (`localStorage`, `sessionStorage`, `IndexedDB`), remove all Supabase configuration, binary upload services, and environment guards, and enforce single-source edge-authenticated security primitives backed exclusively by Cloudflare KV:

1. **Eliminate All Browser Storage Primitives (`src/utils/storage.ts`, `src/utils/storageAdapter.ts`, `src/services/historyStorage.ts`)**:
   - Delete `src/services/historyStorage.ts` (`IndexedDB` `history_store` wrapper) and `src/utils/storageAdapter.ts` (`localStorageAdapter`) completely, and remove their re-exports from `src/index.ts`.
   - Strip `getStorage()`, `getPersistentStorage()`, and `purgeLegacyDocumentStorage()` from `src/utils/storage.ts` (or delete `src/utils/storage.ts`). No service, hook, or utility anywhere in `src/` may read or write `window.localStorage`, `window.sessionStorage`, or `window.indexedDB`.
2. **Eliminate Supabase Configuration, Binary Media Service & Write Guards (`src/utils/supabase-config.ts`, `src/services/mediaService.ts`, `src/utils/supabase-write-guard.ts`, `src/utils/runtime-env.ts`)**:
   - Delete `src/utils/supabase-config.ts`, `src/utils/supabase-write-guard.ts`, `src/utils/runtime-env.ts`, and `src/services/mediaService.ts` (removing their exports from `src/index.ts`).
   - In `src/components/dev/UniversalEditModal.tsx` (L20, L430–458), remove `uploadMediaAsset` and the Supabase Storage binary upload handler so document/file links operate strictly via external/Google Drive URLs with zero Supabase Storage dependency.
3. **Edge-Authoritative PIN Verification, Rate-Limiting & Opaque Lock Token (`src/utils/devSecurity.ts`, `src/edge/handlers/lockHandler.ts`)**:
   - Remove `EXPECTED_PIN_HASH`, `getDevSalt()` fallback chains, `getSessionUnlockTime()`, `setSessionUnlockTime()`, and all `localStorage` / `sessionStorage` lockout counters (`_dev_failed_attempts`, `_dev_lockout_until`, `_dev_unlocked_at`) from `src/utils/devSecurity.ts`.
   - Do **not** bundle `expectedPinHash` or `securitySalt` in client-side `EngineConfig`: execute PIN hashing, verification, and brute-force rate-limiting (`lock:pin_ratelimit`) exclusively on the Cloudflare Edge inside `POST /api/lock` (`src/edge/handlers/lockHandler.ts`, reading `env.DEV_PIN_HASH` and `env.DEV_SECURITY_SALT` and failing stop with HTTP 503 if unconfigured).
   - Upon valid PIN verification, `POST /api/lock` issues an opaque, cryptographically random `lockToken` stored in KV `lock:coordinator` and held purely in React state inside `DeveloperModeContext` (sent via `Authorization: Bearer <lockToken>` on all mutating `/api/draft`, `/api/publish`, `/api/history/restore`, and `/api/lock` calls). Re-authenticating with a valid PIN at `POST /api/lock` supersedes any stale lock from a reloaded tab, preventing self-lockout on page refresh with zero `sessionStorage` usage.

## 🔍 Forensic Audit Findings Addressed

1. **[V1.1] Browser Storage Usage & `localStorage` → `sessionStorage` Silent Fallback**

   - **Locations**: [storage.ts](file:///Users/francisdave/Documents/folio/src/utils/storage.ts#L5-L18), [devSecurity.ts](file:///Users/francisdave/Documents/folio/src/utils/devSecurity.ts#L265-L278)
   - **Conflicting Sources / Fallback Chain**: `window.localStorage` → `window.sessionStorage` → `null`
   - **Why It Violates SSOT**: Uses browser-local storage and silently falls back across two incompatible browser storage engines instead of persisting state exclusively in Cloudflare KV.
2. **[V1.2] 4-Tier Security Salt & PIN Hash Fallback Chain + Browser Lockout Counters**

   - **Locations**: [devSecurity.ts](file:///Users/francisdave/Documents/folio/src/utils/devSecurity.ts#L10-L20), [devSecurity.ts](file:///Users/francisdave/Documents/folio/src/utils/devSecurity.ts#L166-L184), [devSecurity.ts](file:///Users/francisdave/Documents/folio/src/utils/devSecurity.ts#L265-L340)
   - **Conflicting Sources / Fallback Chain**:
     - Salt: `salt` arg → `getEngineConfig().securitySalt` → `import.meta.env.VITE_DEV_SALT` → `(ns || getStorageNamespace()) + "_dev_salt_v1"`
     - PIN Hash: `expectedHash` arg → `getEngineConfig().expectedPinHash` → `import.meta.env.VITE_DEV_PIN_HASH` → hardcoded `EXPECTED_PIN_HASH` (`'73b1e1cccbe22119e026c333e9de035db2a553f8acecdb5406af95f59bf46178'`)
     - Lockout state: `localStorage` → `sessionStorage` (`_dev_failed_attempts`, `_dev_lockout_until`)
   - **Why It Violates SSOT**: Authentication parameters are resolved via a 4-tier fallback chain ending in hardcoded default credentials, and rate-limit counters are stored in browser storage instead of Cloudflare KV.
3. **[V1.3] Startup Purge Conflicts with Runtime `localStorage` Writers**

   - **Locations**: [storage.ts](file:///Users/francisdave/Documents/folio/src/utils/storage.ts#L27-L69)
   - **Conflicting Sources / Fallback Chain**: `purgeLegacyDocumentStorage()` deletes `_draft_canvas_`, `_canvas_`, `_live_canvas_`, and `_content_overrides` at module load while `contentDb.ts`, `canvasLayoutService.ts`, and `historyService.ts` re-create them during the session.
   - **Why It Violates SSOT**: Treats `localStorage` as both forbidden legacy bloat (on startup) and active shadow persistence (at runtime).
4. **[V9.2 (Part A)] Supabase Client Config & Missing-Table Session Memoizer**

   - **Locations**: [supabase-config.ts](file:///Users/francisdave/Documents/folio/src/utils/supabase-config.ts#L1-L140)
   - **Conflicting Sources / Fallback Chain**: Supabase REST tables + in-memory `missingTables` Set + `window.sessionStorage` (`_missing_supabase_tables`).
   - **Why It Violates SSOT**: Introduces a second backend (Supabase) alongside Cloudflare KV and caches negative schema availability in `sessionStorage` and module memory.
