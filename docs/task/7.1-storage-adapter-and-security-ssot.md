## 🎯 Purpose & Scope

Eliminate all browser storage (`localStorage`, `sessionStorage`, `IndexedDB`), remove Supabase configuration and table memoizers, and enforce single-source security primitives backed exclusively by `EngineConfig` and Cloudflare KV:
1. **Eliminate Browser Storage Primitives (`src/utils/storage.ts`, `src/services/historyStorage.ts`)**:
   - Delete `src/services/historyStorage.ts` (`IndexedDB` `history_store` wrapper) completely.
   - Strip `getStorage()`, `getPersistentStorage()`, and `purgeLegacyDocumentStorage()` from `src/utils/storage.ts`. No service, hook, or utility may read or write `window.localStorage`, `window.sessionStorage`, or `window.indexedDB`.
2. **Eliminate Supabase Configuration & Missing-Table Memoizer (`src/utils/supabase-config.ts`)**:
   - Delete `src/utils/supabase-config.ts` (`getSupabaseConfig()`, `isTableAvailable()`, `markTableMissing()`, `missingTables` Set, and `_missing_supabase_tables` in `sessionStorage`). Cloudflare KV is the sole persistence backend across all domains.
3. **Single Security Credential Source & KV Rate-Limiting (`src/utils/devSecurity.ts`)**:
   - Resolve `securitySalt` and `expectedPinHash` strictly from `getEngineConfig()` (the single runtime configuration authority), failing stop if unconfigured instead of cascading across 4 fallback tiers into hardcoded cleartext-derived defaults (`EXPECTED_PIN_HASH`).
   - Eliminate browser-side PIN lockout storage (`getPersistentStorage()`, `localStorage` / `sessionStorage` keys `_dev_failed_attempts`, `_dev_lockout_until`, `_dev_unlocked_at`). Track PIN rate-limiting and lockout state directly in Cloudflare KV (`lock:pin_ratelimit`) inside the atomic `POST /api/lock` acquisition endpoint so brute-force protection cannot be bypassed by clearing browser storage or switching tabs/devices.

## 🔍 Forensic Audit Findings Addressed

1. **[V1.1] Browser Storage Usage & `localStorage` → `sessionStorage` Silent Fallback**
   - **Locations**: [storage.ts](file:///Users/francisdave/Documents/folio/src/utils/storage.ts#L5-L18), [devSecurity.ts](file:///Users/francisdave/Documents/folio/src/utils/devSecurity.ts#L265-L278)
   - **Conflicting Sources / Fallback Chain**: `window.localStorage` → `window.sessionStorage` → `null`
   - **Why It Violates SSOT**: Uses browser-local storage and silently falls back across two incompatible browser storage engines instead of persisting state exclusively in Cloudflare KV.

2. **[V1.2] 4-Tier Security Salt & PIN Hash Fallback Chain + Browser Lockout Counters**
   - **Locations**: [devSecurity.ts](file:///Users/francisdave/Documents/folio/src/utils/devSecurity.ts#L10-L20), [devSecurity.ts](file:///Users/francisdave/Documents/folio/src/utils/devSecurity.ts#L166-L184), [devSecurity.ts](file:///Users/francisdave/Documents/folio/src/utils/devSecurity.ts#L265-L340)
   - **Conflicting Sources / Fallback Chain**:
     - Salt: `salt` arg → `getEngineConfig().securitySalt` → `import.meta.env.VITE_DEV_SALT` → `(ns || getStorageNamespace()) + "_dev_salt_v1"`
     - PIN Hash: `expectedHash` arg → `getEngineConfig().expectedPinHash` → `import.meta.env.VITE_DEV_PIN_HASH` → hardcoded `EXPECTED_PIN_HASH` (`'73b1e1cccbe22119e026c333e9de035db2a553f8acecdb5406af95f59bf46178'`)
     - Lockout state: `localStorage` → `sessionStorage` (`_dev_failed_attempts`, `_dev_lockout_until`)
   - **Why It Violates SSOT**: Authentication parameters are resolved via a 4-tier fallback chain ending in hardcoded default credentials, and rate-limit counters are stored in browser storage instead of Cloudflare KV.

3. **[V1.3] Startup Purge Conflicts with Runtime `localStorage` Writers**
   - **Locations**: [storage.ts](file:///Users/francisdave/Documents/folio/src/utils/storage.ts#L27-L69)
   - **Conflicting Sources / Fallback Chain**: `purgeLegacyDocumentStorage()` deletes `_draft_canvas_`, `_canvas_`, `_live_canvas_`, and `_content_overrides` at module load while `contentDb.ts`, `canvasLayoutService.ts`, and `historyService.ts` re-create them during the session.
   - **Why It Violates SSOT**: Treats `localStorage` as both forbidden legacy bloat (on startup) and active shadow persistence (at runtime).

4. **[V9.2 (Part A)] Supabase Client Config & Missing-Table Session Memoizer**
   - **Locations**: [supabase-config.ts](file:///Users/francisdave/Documents/folio/src/utils/supabase-config.ts#L1-L140)
   - **Conflicting Sources / Fallback Chain**: Supabase REST tables + in-memory `missingTables` Set + `window.sessionStorage` (`_missing_supabase_tables`).
   - **Why It Violates SSOT**: Introduces a second backend (Supabase) alongside Cloudflare KV and caches negative schema availability in `sessionStorage` and module memory.
