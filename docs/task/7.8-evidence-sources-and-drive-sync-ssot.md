Eliminate `src/services/sourceService.ts` (Supabase `engine_sources`, module-level `inMemoryRegistry`, `localStorage` `_evidence_cache_v2`, and static `src/data/source-sources.json`), eliminate static `src/data/node-nodes.json` fallbacks, eliminate `ContentDB` `source.<id>.source` coupling, and embed all evidence gallery metadata and synced photos directly inside `GalleryElement` on the `NodeCanvasDocument` AST stored in Cloudflare KV:
1. **Self-Contained `GalleryElement` in Canvas AST (`src/types/canvas.ts`, `src/components/canvas/CanvasGallery.tsx`, `src/components/source/SourceGallery.tsx`, `src/hooks/useDrivePhotoSync.ts`)**:

Zero Supabase queries, zero `localStorage` reads/writes, zero module-level `inMemoryRegistry`, and zero fallback to `source-sources.json` or `node-nodes.json`.
   - **Dev Mode (`isDevMode = true`)**: Linking a Google Drive folder in `LinkFolderModal` or syncing Drive photos via `useDrivePhotoSync` updates the `GalleryElement` (`driveUrl`, `title`, `description`, `lastVerified`, `syncedPhotos`) directly inside the `NodeCanvasDocument` AST and persists it to Cloudflare KV `draft:workspace` via `PUT /api/draft`—failing stop if the KV write fails.
2. **Eliminate `src/services/sourceService.ts`, `src/hooks/useSourcePoint.ts`, and `getSourceSource()` (`src/utils/source.ts`)**:
   - Delete `src/services/sourceService.ts` (eliminating `inMemoryRegistry`, `_evidence_cache_v2` in `localStorage`, `source-sources.json`, and Supabase `engine_sources`).
   - Remove `getSourceSource()` from `src/utils/source.ts` (which read `ContentDB` `source.${key}.source` layered over `source-sources.json`), retaining only pure URL extraction/validation utilities (`extractDriveFolderId`, `isValidDriveFolderUrl`).
   - Remove `import rawNodeData from '../../data/node-nodes.json'` from `src/components/canvas/CanvasGallery.tsx`.
   - Remove `DevActionAffordance` `pointId="source.${pointId}.source"` (`ContentDB` binding) from `src/components/source/SourceFolderAttachment.tsx`.
3. **Fail-Stop Drive Verification & Subfolder Scanning (`src/services/driveVerificationService.ts`, `src/services/drivePhotoSyncService.ts`, `src/components/source/LinkFolderModal.tsx`)**:
   - In `verifyDriveFolderUrl()`, fail stop on missing API key, API key referrer error, HTTP 4xx/5xx, or network timeout, and remove the secondary `files.list` fallback when `files.get` returns 404. Block saving in `LinkFolderModal.tsx` unless `currentResult.status === 'valid'`.
   - In `fetchDriveFolderImages()`, do not swallow subfolder scan errors (`catch (subfolderErr)` at L368); rethrow so `syncFolderPhotos` fails stop instead of pruning subfolder photos.

## 🏛️ Karpathy Heuristics & Superpowers TDD

1. **Think Before Coding**:
   - Embedding `syncedPhotos`, `driveUrl`, `title`, `description`, and `lastVerified` directly inside `GalleryElement` on the `NodeCanvasDocument` AST eliminates `sourceService.ts`, `useSourcePoint.ts`, `source-sources.json`, and `node-nodes.json` fallbacks completely!
   - When `fetchDriveFolderImages()` scans subfolders, if a subfolder fetch returns `!subResp.ok` or throws, swallowing that error causes `reconcileDrivePhotos()` to see 0 files from that subfolder and **delete** all existing synced photos from that subfolder. Failing stop on `!subResp.ok` protects existing gallery photos from accidental data loss.
2. **Test-Driven Development (Superpowers)**:
   - Write tests in `tests/ssot-sources-drive.test.ts` verifying:
     - `src/services/sourceService.ts` is deleted, and zero files import `source-sources.json` or `node-nodes.json` or touch `localStorage` (`_evidence_cache_v2`).
     - `CanvasGallery` and `SourceGallery` read and update `driveUrl`, `title`, `description`, and `syncedPhotos` strictly on `GalleryElement` in the `NodeCanvasDocument` AST (persisted to KV `draft:workspace` via `PUT /api/draft`).
     - `LinkFolderModal` blocks saving unless `verifyDriveFolderUrl` returns `status === 'valid'`.
     - `fetchDriveFolderImages` throws if any subfolder query fails instead of returning partial `directImages`.
