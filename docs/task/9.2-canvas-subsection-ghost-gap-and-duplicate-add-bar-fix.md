## 🎯 Purpose & Scope

Eliminate the duplicate `+ Add Element` bar and the intermediate "ghost element" hover zone after Canvas Subsections (`<CanvasSubsection>`) in Developer Mode:
1. Render `<CanvasAddBar barId="sub-top-${child.id}" />` unconditionally right after every subsection heading (`<SectionTitle as="h3">`) in Developer Mode.
2. Remove the duplicate outer `<CanvasAddBar barId="sub-${child.id}" />` (`DocumentCanvas.tsx#L730-L738`) that renders a second back-to-back `+ Add Element` bar after every subsection.
3. Anchor `<CanvasItemControls itemType="subsection">` floating toolbar at the top (`sectionFloatingBar`) instead of vertical center (`top: 50%`) so hovering within a subsection container never floats a toolbar over empty vertical margin space.
4. Ensure `handleExecuteAdd` in `DocumentCanvas.tsx` properly inserts a new `subsection` at `subIdx + 1` in the parent section when triggered from an insertion bar inside a subsection (`targetSubsectionId` present).

## 🔍 Problem Statement

In [DocumentCanvas.tsx#L644-L740](file:///Users/francisdave/Documents/folio/src/components/canvas/DocumentCanvas.tsx#L644-L740), subsection rendering has three interacting bugs:

1. **Duplicate `+ Add Element` Bars After Every Subsection:**
   - When a subsection is empty (`validSubLeaves.length === 0`), `DocumentCanvas.tsx` renders `<CanvasAddBar barId="sub-top-${child.id}" />` inside `<CanvasSubsection>` (`L666-L674`) **and** immediately renders `<CanvasAddBar barId="sub-${child.id}" />` right after `</CanvasSubsection></CanvasItemControls>` (`L730-L738`).
   - When a subsection is non-empty (`validSubLeaves.length > 0`), `sub-top-${child.id}` is omitted (so there is no `+ Add Element` bar right after the subsection heading!), while the last leaf inside the subsection renders `<CanvasAddBar barId="leaf-${subLeaf.id}" />` (`L713-L723`) **and** `DocumentCanvas.tsx` immediately renders `<CanvasAddBar barId="sub-${child.id}" />` (`L730-L738`) right after `</CanvasSubsection>`.
   - In both cases, two `+ Add Element` bars are rendered consecutively at the end of the subsection.

2. **The "Ghost Element" Between the Two `+ Add Element` Bars:**
   - `<CanvasSubsection>` (`CanvasContainers.module.css#L28-L45`) applies `margin-bottom: var(--space-6)` (`24px`) on `.subsection` and `margin-top: var(--space-3)` (`12px`) on `.subsectionBody`, while each `.addBarGutter` has `margin: var(--space-3) 0` (`12px`).
   - Because `sub-top-${child.id}` (or `leaf-${lastLeaf.id}`) is rendered **inside** `<CanvasItemControls itemType="subsection"><CanvasSubsection>`, and `sub-${child.id}` is rendered **outside** `</CanvasItemControls>`, there is a `48px` blank vertical region between the two `+ Add Element` bars that still belongs to `div.itemControlsWrapper[data-canvas-item-type="subsection"]`.
   - Furthermore, in [CanvasItemControls.tsx#L128-L130](file:///Users/francisdave/Documents/folio/src/components/canvas/CanvasItemControls.tsx#L128-L130), only `itemType === 'section'` uses `.sectionFloatingBar` (`top: var(--space-4)`), whereas `itemType === 'subsection'` uses `.itemControlsFloatingBar` (`top: 50%`). When the user's cursor enters the empty gap below `sub-top-${child.id}` (and above `sub-${child.id}`), `:hover:not(:has(.addBarGutter:hover))` activates the subsection's floating toolbar in the empty space between the two `+ Add Element` bars—making it appear as though an invisible "ghost element" is sitting after the subsection.

## 🏛️ Karpathy Heuristics & Rules

1. **Think Before Coding:**
   - Trace the visual sequence of `CanvasAddBar`s for both empty and populated subsections once `sub-top-${child.id}` is always rendered and `sub-${child.id}` is removed:
     - **Empty subsection:** `Subsection Heading` → `sub-top-${child.id}` (1 bar total).
     - **Subsection with leaves `[L0, L1]`:** `Subsection Heading` → `sub-top-${child.id}` → `L0` → `leaf-${L0.id}` → `L1` → `leaf-${L1.id}` (1 bar after each visual element; zero consecutive duplicate bars).
   - Trace what happens if a user clicks `+ Add Element` on `sub-top-${child.id}` or `leaf-${subLeaf.id}` (where `targetSectionId = section.id` and `targetSubsectionId = child.id`) and selects `Subsection`:
     - In `handleExecuteAdd` (`DocumentCanvas.tsx#L360-L372`), if `targetSubsectionId` is provided, the new subsection must be inserted into `targetSectionId` right after `targetSubsectionId` (`subIdx + 1`) rather than using `targetIndex` (which is the leaf index inside `targetSubsectionId`).
2. **Make Surgical Changes:**
   - Modify `DocumentCanvas.tsx` and `CanvasItemControls.tsx` only where subsection insertion bars and floating bar positioning are defined.
3. **Verify Everything:**
   - Verify with unit/component tests that an empty subsection renders exactly 1 `CanvasAddBar` (`sub-top-${child.id}`) after its title, and a subsection with `N` leaves renders `sub-top-${child.id}` plus `N` leaf `CanvasAddBar`s (never `sub-${child.id}`).
