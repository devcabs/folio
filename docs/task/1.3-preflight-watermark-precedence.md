## 🎯 Purpose & Scope

Codify the definitive precedence rule for which source of truth wins when `EngineConfig.contentVersion` and `localStorage` disagree on the current content watermark. This prevents silent session regressions where a user's acknowledged migrations are un-acknowledged on next boot simply because the host app passed an older `contentVersion`. The resolution logic must live in a dedicated utility — not inline inside the service — so it is independently testable and unambiguous.

---

## 🔍 Problem Statement

Two locations can declare the content watermark: `EngineConfig.contentVersion` (set by the consumer app at boot) and `localStorage` (set at runtime when the user clicks "Mark as Migrated"). These can silently conflict: if `EngineConfig.contentVersion` is `'0.1.1'` but `localStorage` says `'0.1.3'` (from a previous session), re-reading `EngineConfig.contentVersion` on next boot reverts the user's acknowledgment. The precedence rule is never defined — this must be codified before the service is built.

## 📄 Key Files to Create / Modify

1. **`src/utils/semver-utils.ts`** *(New — src-side mirror)*
   - Re-export `compareSemver` and `isValidSemver` for use inside the library bundle.
   - `scripts/` is not bundled into `dist/` — the src-side copy ensures the library itself can use these utilities without depending on the scripts directory.
   - Implementation must be identical to `scripts/lib/semver-utils.ts` (task 1.1). Keep in sync or extract to a shared location if the build system supports it.
   - Exports: `compareSemver(a: string, b: string): -1 | 0 | 1`, `isValidSemver(v: string): boolean`.

2. **`src/utils/watermarkResolver.ts`** *(New)*
   - `resolveContentWatermark(configVersion: string | undefined, storage: StorageAdapter): string`
     - Precedence rule: return the **higher** of `configVersion` and the value read from storage.
     - Use `compareSemver` from `./semver-utils` for the comparison.
     - If `configVersion` is `undefined` or empty string, use the storage value.
     - If the storage value is `null` or empty string, use `configVersion`.
     - If both are `undefined`/`null`/empty, return `'0.0.0'` (oldest possible — forces all migrations to show as pending).
   - `updateWatermark(newVersion: string, storage: StorageAdapter): void`
     - Reads the current resolved watermark by calling `resolveContentWatermark(undefined, storage)` (storage-only resolution).
     - Only writes `newVersion` to storage if `compareSemver(newVersion, current) === 1` (strictly greater).
     - Never downgrades the watermark.
     - Storage key: `'folio_content_version'` (must be a named constant, not a magic string inline).

3. **`src/services/migrationService.ts`** *(Pre-wire for 1.11)*
   - `getContentVersionWatermark(config: EngineConfig, storage?: StorageAdapter): string`
     - MUST delegate to `resolveContentWatermark(config.contentVersion, storage ?? localStorageAdapter)`.
     - Zero inline precedence logic allowed here — all logic lives in `watermarkResolver.ts`.

4. **`src/index.ts`** *(Modify)*
   - Export `resolveContentWatermark` and `updateWatermark` from `./utils/watermarkResolver`.
   - Export `compareSemver` and `isValidSemver` from `./utils/semver-utils`.
