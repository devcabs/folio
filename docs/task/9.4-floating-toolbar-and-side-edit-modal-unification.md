## 🎯 Purpose & Scope

Ensure that clicking the Edit icon (`✎`) on the floating toolbar (`CanvasItemControls`) on top of any canvas element opens the **exact same modal or drawer** with the **exact same initial data and save pipeline** as clicking the `✎ Edit` button beside that canvas element:
1. **Gallery (`CanvasGallery` / `SourceGallery`)**: Both the floating toolbar Edit button and the side `✎ Edit` button beside the gallery must open the canonical `<LinkFolderModal>` (which includes `Folder Label`, `Google Drive Folder URL`, the `Verify` button, `Test Link ↗`, and the mandatory Google Drive API folder verification gate).
2. **Chart (`CanvasChart` / `ChartCard`)**: Both the floating toolbar Edit button and the side `✎ Edit` button beside the chart must open `<ChartConfigDrawer>` pre-populated with the chart element's current `initialConfig` (`element.config`) and wired to persist updated `config` and `dataset` into the `ChartElement` on the `NodeCanvasDocument` AST.

## 🔍 Problem Statement

Currently, the two canvas element types that render a side `✎ Edit` button (`sideEditWrapper`) beside the element open different modals or unconfigured drawer instances when triggered from the floating toolbar (`CanvasItemControls`) vs. the side `✎ Edit` button:

### 1. Gallery Modal Mismatch (`UniversalEditModal` vs `LinkFolderModal`)
- **Side `✎ Edit` Button (`SourceGallery.tsx#L452-L466` & `L538-L547`)**:
  Clicking `✎ Edit` beside a gallery sets `isSourceModalOpen = true`, which opens **`<LinkFolderModal>`** (`title="Link Folder"`). `LinkFolderModal` provides URL syntax validation, the `Verify` button (`verifyDriveFolderUrl`), auto-filling `Folder Label` from Google Drive metadata, `Test Link ↗`, and the fail-stop verification gate (`currentResult.status === 'valid'`) before persisting via `onUpdateGallery({ driveUrl: newUrl, title: newTitle })`.
- **Floating Toolbar Edit Button (`DocumentCanvas.tsx#L310-L325` & `L695` / `L754`)**:
  Clicking the Edit icon (`✎`) on `CanvasItemControls` on top of a gallery calls `handleEditLeaf(leaf)` in `DocumentCanvas.tsx`:
  ```tsx
  } else if (leaf.type === 'gallery') {
    pointId = leaf.pointId || leaf.titlePointId;
    initialData = {
      title: leaf.title || '',
      driveUrl: leaf.driveUrl || '',
    };
  }
  setActiveModal({
    isOpen: true,
    mode: 'edit',
    elementType: leaf.type,
    itemId: leaf.id,
    pointId,
    initialData,
  });
  ```
  This opens **`<UniversalEditModal elementType="gallery">`** (`title="Edit Gallery"`), a completely different modal that lacks the `Verify` button, `Test Link ↗`, Drive folder title auto-discovery, and the Google Drive API folder verification gate.

### 2. Chart Drawer State & Persistence Mismatch
- **Side `✎ Edit` Button (`ChartCard.tsx#L260-L304`)**:
  Clicking `✎ Edit` beside a chart opens `ChartCard`'s internal `<ChartConfigDrawer>` with `initialConfig={config || undefined}` and `onDeployed={onConfigUpdated}` (which updates `ChartElement` in the AST).
- **Floating Toolbar Edit Button (`DocumentCanvas.tsx#L287-L294` & `L834-L882`)**:
  Clicking the Edit icon (`✎`) on `CanvasItemControls` on top of a chart calls `handleEditLeaf(leaf)` in `DocumentCanvas.tsx`:
  ```tsx
  if (leaf.type === 'chart') {
    setActiveChartDrawer({
      isOpen: true,
      mode: 'edit',
      chartId: leaf.chartId,
    });
    return;
  }
  ```
  And `DocumentCanvas.tsx` mounts `<ChartConfigDrawer>` at `L834-L882`:
  - **Missing `initialConfig`:** `ActiveChartDrawerState` does not store `initialConfig` or `elementId`, and `<ChartConfigDrawer>` is not passed `initialConfig`. Because Epic 7 removed the legacy sidecar `chartSourceService` cache, opening `ChartConfigDrawer` from the floating toolbar opens a completely **blank/reset drawer in Step 1** instead of loading the chart's existing configuration!
  - **Missing `mode === 'edit'` Persistence:** `onDeployed` in `DocumentCanvas.tsx#L841-L880` only executes `if (activeChartDrawer.mode === 'add') { ... }`. When `mode === 'edit'`, clicking Deploy Chart simply calls `setActiveChartDrawer(null)` and **discards all changes without updating the AST**!

## 🏛️ Karpathy Heuristics & Rules

1. **Think Before Coding:**
   - Every edit affordance for the same canvas element (floating toolbar `Edit` icon, side `✎ Edit` button, fallback card `✎ Edit` / `Attach Drive Folder`) must route to one authoritative modal/drawer with identical props and persistence.
   - Check whether adding a new Gallery (`mode === 'add'`, `type === 'gallery'`) should also use `<LinkFolderModal>` so newly created galleries are verified against Google Drive API on creation as well.
2. **Make Surgical Changes:**
   - In `DocumentCanvas.tsx`, replace the `elementType === 'gallery'` modal branch with `activeGalleryModal` state backed by `<LinkFolderModal>`, and pass `onEdit={() => handleEditLeaf(leaf)}` down to `CanvasGallery` → `SourceGallery` so both the floating toolbar Edit button and the side `✎ Edit` button open the same `<LinkFolderModal>`.
   - In `DocumentCanvas.tsx`, extend `ActiveChartDrawerState` with `elementId?: string` and `initialConfig?: SheetChartConfig`, pass `initialConfig` to `<ChartConfigDrawer>`, handle `mode === 'edit'` in `onDeployed` via `updateItem<ChartElement>`, and pass `onEdit={() => handleEditLeaf(leaf)}` down to `CanvasChart` → `ChartCard` so both the floating toolbar Edit button and the side `✎ Edit` button open the same `<ChartConfigDrawer>`.
3. **Verify Everything:**
   - Write tests confirming that clicking the floating toolbar Edit button and clicking the side `✎ Edit` button on both `CanvasGallery` and `CanvasChart` open the exact same modal/drawer with identical initial values and persist changes to the Canvas AST.
