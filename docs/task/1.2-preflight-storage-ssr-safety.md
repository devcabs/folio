## 🎯 Purpose & Scope

Introduce a lightweight storage adapter abstraction that guards all `localStorage` access, preventing SSR crashes and silent `SecurityError` failures in private/incognito mode. This adapter becomes the mandatory interface for all watermark and migration state persistence throughout the codebase, enabling full dependency injection in both production and test contexts.

---

## 🔍 Problem Statement

`migrationService.ts` (task 1.11) will call `localStorage` directly in a service exported from the library. This crashes in any SSR environment (Next.js, Remix, Vite SSR) because `localStorage` does not exist server-side. Even in browser-only apps, it fails silently in private/incognito mode on some browsers by throwing `SecurityError`. The fix is a lightweight storage adapter that guards all `localStorage` access.

---

## 📄 Key Files to Create / Modify

1. **`src/utils/storageAdapter.ts`** *(New)*
   - Define `StorageAdapter` interface:
     ```ts
     interface StorageAdapter {
       getItem(key: string): string | null;
       setItem(key: string, value: string): void;
       removeItem(key: string): void;
     }
     ```
   - `localStorageAdapter: StorageAdapter`:
     - Wraps `localStorage` with a `typeof window !== 'undefined'` guard at the call site (not at module load time — the guard must be inside each method so the module can be safely imported in SSR without a top-level window check failing).
     - If `window` is not available or `localStorage` throws a `SecurityError`, all methods are no-ops and `getItem` returns `null`.
     - Wrap `localStorage` access in a `try/catch` to handle `SecurityError` in private browsing mode.
   - `createInMemoryAdapter(): StorageAdapter`:
     - Returns a fresh `Map<string, string>`-backed adapter instance.
     - Each call to `createInMemoryAdapter()` creates a completely isolated instance — no shared state.
     - Used in tests and SSR contexts.
   - Export `StorageAdapter` (type), `localStorageAdapter`, and `createInMemoryAdapter`.

2. **`src/services/migrationService.ts`** *(Pre-wire for 1.11)*
   - Define the service factory/functions to accept an optional `storage?: StorageAdapter` parameter (dependency injection pattern).
   - Default to `localStorageAdapter` when `storage` is not provided.
   - All `localStorage.getItem/setItem/removeItem` calls MUST go through the injected adapter — NEVER call `localStorage` directly anywhere in the service.
   - Stub out the service shape now so tasks 1.11, 1.3, and 1.8 can reference consistent function signatures.

3. **`src/index.ts`** *(Modify)*
   - Export `StorageAdapter` (type), `localStorageAdapter`, and `createInMemoryAdapter` from `./utils/storageAdapter`.
