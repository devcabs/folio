## 🎯 Purpose & Scope

Resolve two critical lifecycle race conditions and event dispatch gaps:
1. Protect `initDraftSession()` against parallel execution races when Developer Mode is quickly toggled or unlocked across multiple components.
2. Ensure that restoring a historical snapshot via `restoreUnifiedSnapshot()` dispatches reactive canvas update events, so that currently rendered view components immediately reflect the restored state without requiring a manual page refresh.

---

## 🔍 Problem Statement

1. **In `src/services/draftService.ts` (`initDraftSession`)**:
   - Lines 460–537 query Supabase cloud via `fetchActiveCloudDraft()`.
   - There is no in-flight promise sentinel. If two components or handlers trigger `initDraftSession()` concurrently, two parallel network requests run. The second one can overwrite `inMemoryDraftCanvases` with older or conflicting data, corrupting the draft sandbox state.

2. **In `src/services/historyService.ts` (`restoreUnifiedSnapshot`)**:
   - Lines 493–498 iterate through `getActiveNodeIds()` calling `saveNodeCanvas(canvasDoc)`.
   - However, when restoring into canonical live storage, no canvas change events (`EVENT_LIVE_CANVAS_CHANGE`) or aggregate change notifications (`dispatchAggregateCanvasChange(false)`) are fired.
   - Any mounted `useDocumentCanvas` or `useNodeCanvas` hooks on the page continue rendering the prior canvas until the user navigates away or refreshes the page!
