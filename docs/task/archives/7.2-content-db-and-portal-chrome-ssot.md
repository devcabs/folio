## 🎯 Purpose & Scope

Eliminate all module-level memory caches (`liveMemoryCache`, `draftMemoryCache`, `inMemoryLiveStores`, `inMemoryDraftStores`, `draftTombstones`, `hasCompletedHydration`), `localStorage` shadow keys (`_live_content_overrides`, `_draft_content_overrides`, `_content_overrides`), `useSyncExternalStore` singleton dependencies, and silent error swallowing in `src/utils/contentDb.ts`, `src/hooks/useContent.ts`, and `src/hooks/usePortalChromeHydration.ts`:
1. **Direct Cloudflare KV Authority per Mode via React Context (`src/hooks/usePortalChromeHydration.ts`, `src/hooks/useContent.ts`, `src/utils/contentDb.ts`)**:
   - **Public Mode (`isDevMode = false`)**: Hydrates `contentOverrides` directly from Cloudflare KV `portal:manifest` via `GET /api/public/manifest` into a dedicated `PortalChromeContext` (re-fetching `GET /api/public/manifest` whenever `isDevMode` transitions from `true` back to `false`).
   - **Dev Mode (`isDevMode = true`)**: Reads `contentOverrides` from the active `draft:workspace` hydrated via `GET /api/draft` and persists edits/resets directly to `draft:workspace` via `PUT /api/draft` (with `Authorization: Bearer <lockToken>` and `expectedUpdatedAt` concurrency check).
   - **Zero Module-Level Shadow Stores & Replace `useSyncExternalStore`**: Delete `liveMemoryCache`, `draftMemoryCache`, `inMemoryLiveStores`, `inMemoryDraftStores`, `draftTombstones`, and `keySubscribers` from `src/utils/contentDb.ts`, and delete the module-level `let hasCompletedHydration = false` singleton from `src/hooks/usePortalChromeHydration.ts`. Refactor `useContent.ts` from `useSyncExternalStore` (which required a synchronous module-level cache) to consume `PortalChromeContext` directly.
2. **Zero Cross-Channel Fallthrough & Zero Tombstones**:
   - Because `draft:workspace.contentOverrides` in Cloudflare KV is initialized as a complete clone of `portal:manifest.contentOverrides` when a draft session starts, resetting a key in Dev Mode simply deletes that key from `draft:workspace.contentOverrides` via `PUT /api/draft`. Reading in Dev Mode inspects **only** `draft:workspace.contentOverrides` (falling back to the component's static `defaultText` prop if the key is not overridden), eliminating `draftTombstones` and cross-channel live-cache fallthrough.
3. **Strict Fail-Stop Portal Chrome Hydration & Mutation**:
   - If `GET /api/public/manifest`, `GET /api/draft`, or `PUT /api/draft` fails or returns non-2xx, fail stop immediately: surface `hydrationError: string | null` and render `<TopErrorBanner />` (on read failure) or reject the edit and display an error alert (on write failure). Never swallow errors with `.catch(() => {})`.

## 🔍 Forensic Audit Findings Addressed

1. **[V2.1] `ContentDB` 4-Tier Read Fallback, Module-Level Singletons, `localStorage` Shadowing & Silent Quota Swallowing**
   - **Locations**: [contentDb.ts](file:///Users/francisdave/Documents/folio/src/utils/contentDb.ts#L16-L110), [contentDb.ts](file:///Users/francisdave/Documents/folio/src/utils/contentDb.ts#L365-L377)
   - **Conflicting Sources / Fallback Chain**:
     - `loadLiveCache()` (L35–59): `liveMemoryCache` → `localStorage` (`_live_content_overrides`) → `localStorage` (`_content_overrides`) → `inMemoryLiveStores` Map → `{}`
     - `loadDraftCache()` (L61–81): `draftMemoryCache` → `localStorage` (`_draft_content_overrides`) → `inMemoryDraftStores` Map → `{}`
     - `saveLiveCache()` (L83–95) & `saveDraftCache()` (L97–110): Dual-writes to module Maps and `localStorage`, silently ignoring `localStorage` exceptions in `catch {}`.
   - **Why It Violates SSOT**: Stores content overrides across module singletons, namespace Maps, and `localStorage` instead of reading and writing directly to Cloudflare KV (`portal:manifest` and `draft:workspace`).

2. **[V2.2] Dev-Mode Fallthrough to Live Cache & Ephemeral `draftTombstones` Set**
   - **Locations**: [contentDb.ts](file:///Users/francisdave/Documents/folio/src/utils/contentDb.ts#L33), [contentDb.ts](file:///Users/francisdave/Documents/folio/src/utils/contentDb.ts#L131-L165), [contentDb.ts](file:///Users/francisdave/Documents/folio/src/utils/contentDb.ts#L239-L280)
   - **Conflicting Sources / Fallback Chain**: `draftMemoryCache` (`_draft_content_overrides`) → `draftTombstones` (module-level `Set<string>`) → `liveMemoryCache` (`_live_content_overrides`) → `defaultValue`
   - **Why It Violates SSOT**: Layers module-level draft cache over module-level live cache mediated by an unpersisted `draftTombstones` Set instead of reading strictly from KV `draft:workspace.contentOverrides`.

3. **[V2.3] Silent Error Swallowing in `usePortalChromeHydration`**
   - **Locations**: [usePortalChromeHydration.ts](file:///Users/francisdave/Documents/folio/src/hooks/usePortalChromeHydration.ts#L45-L62), [HeroWelcome.tsx](file:///Users/francisdave/Documents/folio/src/components/layout/HeroWelcome.tsx#L20-L45)
   - **Conflicting Sources / Fallback Chain**: `/api/public/manifest` → `setLiveContentOverrides(..., { memoryOnly: true })` → `HeroWelcome` props (`EngineConfig.branding`) → `DEFAULT_KICKER` / `DEFAULT_TITLE` / `DEFAULT_SUBTITLE`
   - **Why It Violates SSOT**: When `/api/public/manifest` returns HTTP 404/500/503 or fails over the network, `.then((res) => (res.ok ? res.json() : null))` and `.catch(() => {})` silently ignore the failure and render fallback strings instead of failing stop.

   - Portal chrome overrides (`hero.*`, `footer.*`, `node.${id}.title`, `node.${id}.summary`, `node.${id}.kicker`) are small key-value strings stored in `portal:manifest.contentOverrides` (Public Mode) and `draft:workspace.contentOverrides` (Dev Mode).
