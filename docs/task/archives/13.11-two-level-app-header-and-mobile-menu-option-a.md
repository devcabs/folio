## 🎯 Purpose & Scope

Deliver global 2-level site navigation across both desktop and mobile viewports while preserving `AppHeader`'s calm single-row floating glass capsule:
1. **Desktop Single-Row Top Bar + Solid-Surface Level 2 Dropdowns**: Show main chapters in `AppHeader` on **both Home and Node/Subpage routes** (`mobileOnlyNav={false}` in `src/App.tsx`). Clicking a chapter label navigates directly to that chapter; hovering, focusing, or clicking its compact chevron trigger (`▾`) reveals a **solid-surface (`var(--nav-dropdown-bg)` = `var(--folio-bg-surface)`, `var(--nav-dropdown-shadow)` = `var(--shadow-md)`, ZERO glass-on-glass `backdrop-filter`)** dropdown listing direct Level 2 subpages in exact chapter-canvas order.
2. **Overflow Protection & Full Keyboard / Touch Ergonomics**: Handle long chapter lists gracefully (clean truncation / `"More ▾"` overflow bucket when chapter count exceeds comfortable single-row budget, e.g. `> 5` chapters) and implement `ArrowDown`, `ArrowUp`, `Enter`, `Escape`, outside-click dismissal, and touch-tap chevron toggling.
3. **Mobile Hamburger Menu Port (Option A — Strictly 2-Level)**: Replace the legacy in-page sections mobile list on node routes with the **pure 2-level chapter & Level 2 subpage hierarchy** (zero in-page section clutter mixed into the hamburger menu), matching desktop `AppHeader` 1:1.

### Step-by-Step Implementation Blueprint

1. **Extend `AppHeaderProps` in `src/components/layout/AppHeader.tsx`**
   - Add optional `onNavigatePage?: (pageId: string) => void;` and `maxVisibleDesktopItems?: number;` (default `5` for clean single-row capsule balance).
   - Keep `onRoadmapClick`, `onOverviewClick`, `onBrandClick`, `navItems`, `mobileOnlyNav` 100% backward compatible for standalone consumers.

2. **Desktop Single-Row Chapter Links + Solid-Surface Level 2 Dropdowns (`AppHeader.tsx` & `AppHeader.module.css`)**
   - **Layout fix for multi-item single row**: Inspect `AppHeader.module.css` lines 132–142 where `.navLinks` is currently `position: absolute; left: 50%; transform: translate(-50%, -50%)`. When displaying 5 chapters, absolute centering can collide with `.brandGroup` on 1024px–1180px viewports! Switch desktop `.navLinks` to a flex-centered, shrink-safe single row (`flex: 1; justify-content: center; min-width: 0; gap: var(--space-gap-layout);`) with `max-width` truncation (`text-overflow: ellipsis; white-space: nowrap;`) on individual chapter labels so brand + nav never overlap at 1024px+.
   - **Overflow bucket**: If `effectiveNavItems.length > maxVisibleDesktopItems`, render the first `maxVisibleDesktopItems - 1` chapters directly and group remaining chapters inside a `"More ▾"` solid-surface dropdown (each overflow chapter remains clickable and shows its Level 2 subpages indented beneath it).
   - **Split Clickable Chapter + Dropdown Trigger**:
     - For a chapter `NavItem` with `children && children.length > 0`:
       - Render `<div className={styles.navItemGroup}>` containing:
         1. `<a href={item.href} className={`${styles.navLink} ${item.isActive ? styles.navLinkActive : ''}`} aria-current={item.isActive ? 'page' : undefined} onClick={(e) => handleNavClick(item, e)}>{item.label}</a>` — **directly clickable to navigate to the chapter!**
         2. Epic 12's canonical `<IconButton variant="ghost" size="xs" className={styles.dropdownChevronBtn} aria-label={`${item.label} subpages`} aria-haspopup="menu" aria-expanded={isDropdownOpen} aria-controls={`header-dropdown-${item.id || item.label}`} onClick={...}>` containing a crisp thin-stroke `▾` chevron SVG (rotates `180deg` smoothly when open).
       - Hovering the group opens the dropdown (with a brief 180ms leave grace timer matching `CanvasAddBar` diagonal cursor travel); clicking the chevron toggles/pins it on touch and desktop; clicking outside or pressing `Escape` closes it and returns focus to the trigger.
     - **Keyboard navigation**:
       - Pressing `ArrowDown` on the chapter link or chevron opens the dropdown and moves focus to the first Level 2 subpage item.
       - Inside the dropdown (`role="menu"`), `ArrowDown` / `ArrowUp` cycle focus across `role="menuitem"` links, `Home`/`End` jump to first/last, `Escape` closes and returns focus to the chevron button, and `Enter` navigates + closes.
     - **Solid-Surface Styling (`.desktopDropdown` in `AppHeader.module.css`)**:
       - `background: var(--nav-dropdown-bg);` *(solid `var(--folio-bg-surface)` — **STRICTLY NO `backdrop-filter`** per `editorial-restraint.md` §4!)*
       - `border: 1px solid var(--nav-dropdown-border);`
       - `border-radius: var(--nav-dropdown-radius);`
       - `box-shadow: var(--nav-dropdown-shadow);`
       - `z-index: var(--z-dropdown);`
       - Zero horizontal dividing lines between dropdown items (`gap: var(--space-1)`).
       - Full 4-state interactive matrix + Universal Zero Outline Policy (`outline: none;`) on every link and trigger.

3. **Mobile Hamburger Menu Port — Option A (`AppHeader.tsx` & `AppHeader.module.css`)**
   - Migrate the mobile hamburger toggle button (`AppHeader.tsx` line 196) to Epic 12's canonical `<IconButton variant="ghost" size="sm" className={styles.menuToggle} ...>` (zero raw `<button>` in `AppHeader.tsx`; use `<Button variant="ghost" size="xs">` for the `"More ▾"` text+chevron overflow trigger).
   - Remove `'src/components/layout/AppHeader.tsx': new Set(['button'])` from `RAW_CONTROL_EXEMPTIONS` in `tests/canonical-ui-enforcement.test.ts` (line 52) so Epic 12's static guardrail locks in compliance.
   - Inside `#app-mobile-nav` (`.mobileDropdown`):
     - Render solid-surface `background: var(--nav-dropdown-bg);` (no nested glass blur over the glass capsule!).
     - Render each chapter as a clean primary row (clickable to navigate to the chapter + close menu).
     - Beneath any chapter with `item.children && item.children.length > 0`, render its **direct Level 2 subpages** in a calm indented list (`.mobileSubList` -> `.mobileSubNavLink`), strictly capped at 2 levels (zero Level 3+, **zero in-page sections**).
     - Add `max-height: calc(100vh - 110px); overflow-y: auto;` so mobile menus with many Level 2 subpages scroll cleanly inside the viewport.

4. **Wire 2-Level Nav Tree in `src/App.tsx`**
   - Replace `App.tsx` lines 93–104 (`navItems` that previously sent `effectiveNodeSections` on node routes and only `Roadmap`/`Overview` on home) with:
     ```ts
     const siteNavItems = useMemo<NavItem[]>(() => {
       return buildTwoLevelNavTree(
         nodes,
         portalChrome?.pages ?? {},
         activePageId,
         engineConfig.basePath,
         (node) => resolveContent(portalChrome?.contentOverrides ?? {}, `node.${node.id}.title`, node.title)
       );
     }, [nodes, portalChrome?.pages, portalChrome?.contentOverrides, activePageId, engineConfig.basePath]);
     ```
   - Pass `navItems={siteNavItems}`, `mobileOnlyNav={false}` (on BOTH Home and Node/Subpage routes!), and `onNavigatePage={navigateToPage}` into `<AppHeader />` (lines 237–245).
   - Inside `handleNavClick` in `AppHeader.tsx`: when `item.pageId && onNavigatePage`, call `e.preventDefault(); setIsOpen(false); setOpenDropdownId(null); onNavigatePage(item.pageId);`.

- **Single-Row Restraint**: Desktop top bar stays a single clean floating capsule row—never wraps to 2 lines.
- **Option A Mobile Restraint**: Mobile hamburger menu shows strictly chapters + Level 2 subpages—zero in-page section headings mixed in.
- **Canonical UI & 4-State Matrix**: All buttons in `AppHeader.tsx` use Epic 12's canonical `<IconButton>` (dropdown chevron & mobile menu toggle) and `<Button>` (`"More"` overflow trigger), `AppHeader.tsx` is pruned from `RAW_CONTROL_EXEMPTIONS` in `tests/canonical-ui-enforcement.test.ts`, and every interactive control implements Default/Hover/Active/Focus-Visible with `outline: none;`.
