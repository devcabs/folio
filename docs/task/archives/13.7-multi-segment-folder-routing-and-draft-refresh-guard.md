## 🎯 Purpose & Scope

Upgrade Folio Engine's client router (`src/hooks/use-hash-route.ts`) from single-segment `/node/:id/` matching to **arbitrary-depth folder-style routing** (`/node/<chapter>/<subpage>/<nested>/.../`) with:
1. Full backward compatibility for root `/`, `#stage-N`, legacy `#node/:id`, `/page/:id/`, and `EngineConfig.basePath`.
2. **Optimistic Chapter-Prefix Hydration Fallback** (local dev / cold cache when `window.__FOLIO_MANIFEST__` is absent and `portalChrome.isHydrating` is `true`) so deep subpage URLs hold calmly in `'hydrating'` instead of flashing a false 404 before `pages` arrives.
3. **Dev Mode Draft Refresh / Exit Guard**: when an editor exits Dev Mode (or reloads into Public Mode) while viewing an unpublished draft-only subpage, smoothly redirect to the nearest published ancestor chapter (or Home) with a calm informational toast instead of stranding them on a 404.

### Step-by-Step Implementation Blueprint

1. **Extend `RouteType` & `RouteState` in `src/hooks/use-hash-route.ts`**
   - Update `RouteType = "home" | "node" | "page" | "hydrating" | "not-found"`.
   - Extend `RouteState` (line 8) while keeping all existing fields (`type`, `nodeId`, `pageId`, `targetStage`, `rawHash`, `pathname`) 100% backward compatible:
     ```ts
     export interface RouteState {
       type: "home" | "node" | "hydrating" | "not-found";
       /** Resolved root chapter ID (e.g. 'access'), even when viewing a deep subpage */
       nodeId: NodeCode | null;
       /** Resolved active page ID (equals root nodeId on chapters; equals PageNode.id on subpages) */
       pageId: string | null;
       /** Canonical alias for pageId */
       activePageId: string | null;
       /** Resolved root chapter ID alias */
       rootNodeId: NodeCode | null;
       /** Resolved PageNode when viewing a dynamic subpage; null on root chapters / home / 404 */
       pageNode: PageNode | null;
       /** Ordered ancestor chain [rootChapter, ..., currentPage] */
       ancestors: PageAncestorItem[];
       /** Decoded path segments after /node/ (used by Smart 404 fuzzy matcher & nearest-parent recovery) */
       attemptedSegments: string[];
       /** Deepest valid ancestor matched before failure (used by Smart 404) */
       nearestValidAncestor: PageAncestorItem | null;
       targetStage: number | null;
       rawHash: string;
       pathname?: string;
     }
     ```

2. **Upgrade `parseRoute` (line 31)**
   - Add an optional 5th parameter `options?: { pages?: PageRegistry; rootNodes?: NodeItem[]; isHydrating?: boolean }`:
     - Existing 1–4 argument callers (`parseRoute(pathname, hash, validNodes, basePath)`) continue working identically!
     - Resolve `rootNodes = options?.rootNodes ?? getActiveNodes()` and `pages = options?.pages ?? {}`.
   - **Multi-segment path matching**:
     - Replace single-segment regex `/^\/(node|page)\/([a-zA-Z0-9_-]+)\/?$/` with multi-segment matcher `/^\/(node|page)\/(.+?)\/?$/`.
     - Split captured path on `/`, `decodeURIComponent` safely (catching malformed `%` URI sequences -> `'not-found'`), filter empty segments, lowercase -> `segments`.
     - **Case A: Single segment (`segments.length === 1`)**:
       - Match root chapter against `validNodes` / `rootNodes` (identical to existing behavior); set `activePageId = code`, `rootNodeId = code`, `pageNode = null`, `ancestors = [rootAncestor]`, `attemptedSegments = [code]`.
     - **Case B: Multi-segment (`segments.length > 1`)**:
       - Call `resolvePathToPage(segments, rootNodes, pages)` from `pageTreeService.ts`.
       - If `matched === true`: return `type: 'node'`, `nodeId: rootNode.id`, `rootNodeId: rootNode.id`, `pageId: resolvedPageId`, `activePageId: resolvedPageId`, `pageNode`, `ancestors`, `attemptedSegments: segments`, `pathname: buildPagePath(resolvedPageId, rootNodes, pages, effectiveBasePath)`.
       - If `matched === false`:
         - **Optimistic Chapter-Prefix Hydration Guard**: If `options?.isHydrating === true` AND `segments[0]` matches a valid root chapter in `validNodes` / `rootNodes`, return `type: 'hydrating'` (with `rootNodeId: segments[0]`, `attemptedSegments: segments`, `nearestValidAncestor`) so the shell waits calmly until manifest/draft hydration settles!
         - Otherwise return `type: 'not-found'` with `attemptedSegments: segments` and `nearestValidAncestor` (so Smart 404 knows both what was typed and the nearest valid parent!).
   - **Legacy Hash Routes (`#node/...` or `#page/...`)**:
     - Support both `#node/access` and `#node/access/research` via the same segment splitter; upgrade clean URL via `window.history.replaceState` when matched.

3. **Upgrade `useHashRoute` (line 160)**
   - Add optional 3rd parameter `options?: { pages?: PageRegistry; isHydrating?: boolean; isDevMode?: boolean; publishedPages?: PageRegistry; onDraftExitRedirect?: (targetTitle: string) => void }`:
     - Re-evaluate `parseRoute` reactively whenever `window.location` (`popstate` / `hashchange`), `pages`, `isHydrating`, `validNodes`, or `effectiveBasePath` change! (Critical: when `pages` finishes hydrating or a subpage is created/renamed/deleted, `routeState` updates automatically.)
   - **Canonical `navigateToPage(pageId: string, options?: { replace?: boolean; pagesOverride?: PageRegistry })`**:
     - Computes canonical folder URL via `buildPagePath(pageId, getActiveNodes(), options?.pagesOverride ?? pages, effectiveBasePath)`.
     - Calls `cancelCinematicScroll()`, pushes (or replaces if `options?.replace`) via `window.history.pushState`/`replaceState`, scrolls to top (`behavior: "instant"`), and updates `routeState`.
     - Keep `navigateToNode(nodeId)` calling `navigateToPage(nodeId)` for full backward compatibility.
   - **Dev Mode Draft Refresh / Exit Guard**:
     - Track `prevIsDevModeRef` and `lastResolvedRef` (capturing `pageNode` & `ancestors` when on an unpublished draft subpage).
     - When `isDevMode` transitions `true -> false` (editor exits Dev Mode) while viewing a subpage whose `pageId` does NOT exist in `publishedPages` (and `!isHydrating`):
       - Walk `lastResolvedRef.current.ancestors` from deepest to root to find the nearest published ancestor (either a `PageNode` present in `publishedPages` or the root chapter `rootNodeId`).
       - Replace URL via `navigateToPage(nearestPublished.id, { replace: true, pagesOverride: publishedPages })` (or `navigateToHome()` if none).
       - Invoke `onDraftExitRedirect?.(nearestPublished.title)` so `App.tsx` displays a calm `showToast("Returned to <Parent> — unpublished draft subpage is only visible in Dev Mode.", "info")`.

## 🛡️ Architectural & UI/UX Guardrails

- **Malformed URI Safety**: Guard `decodeURIComponent` with `try/catch` so paths containing invalid `%` sequences cleanly resolve to `'not-found'` without throwing.
- **No Unmounted Flash**: During `type === 'hydrating'`, `App.tsx` (wired in `13.10`) renders `<CanvasGhostWireframe />` rather than `<PageNotFound />`.
- **Single Path Authority**: Always compute canonical URLs via `pageTreeService.buildPagePath` — never hand-concatenate `/node/` strings outside `pageTreeService`.
