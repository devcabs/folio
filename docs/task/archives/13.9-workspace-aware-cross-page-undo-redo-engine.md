## 🎯 Purpose & Scope

Transform Folio Engine's active-session Undo/Redo system into a **Workspace-Aware Cross-Page Undo/Redo Engine** so `Cmd+Z` / `Cmd+Shift+Z` works reliably across multi-page editing, page creation, metadata edits, and guarded branch deletion—even after the editor navigates away from the originally edited page:
1. Audit and harden `UndoRedoManager` (`src/services/undoRedoService.ts`) and `UndoRedoContext` (`src/context/UndoRedoContext.tsx`) for `popUndoAsync`, `popRedoAsync`, `clearScope`, async failure rollback, `isTextInput` chord isolation, and automatic history clearance on Dev Mode exit / snapshot restore / publish.
2. Introduce **workspace-addressed atomic transaction commands** (`createWorkspaceUndoCommand`) that capture before/after `canvases` slices, before/after `pages` registry snapshots, and `deletedPageIds`—persisting directly via `commitDraftWorkspaceTransaction` (`enqueueDraftMutation` + `PUT /api/draft`) and broadcasting `EVENT_DRAFT_CANVAS_CHANGE` + `EVENT_DRAFT_CONTENT_CHANGE` + `EVENT_DRAFT_UPDATED_AT_SYNC`, eliminating fragile mounted React hook `documentRef` closures!
3. Wire **automatic route reconciliation**: if an `undo()` or `redo()` removes the subpage the editor is currently viewing, navigate the editor cleanly up to its parent page (or Home if root); if an `undo()` or `redo()` changes the slug of the currently viewed page (or any of its ancestors), reconcile the browser URL via `replaceState` to the updated folder path!
4. Migrate `src/hooks/useDocumentCanvas.ts` mutations (`addSection`, `addSubsection`, `addElement`, `moveItem`, `relocateItem`, `removeItem`, `updateItem`) from local hook closures to workspace-addressed commands and **remove the stale unmount `clearScope(canvasScope)` effect (lines 328–333)** so navigating from Page A to Page B preserves Page A's undo history!

### Step-by-Step Implementation Blueprint

1. **Define Workspace Command Helper in `src/services/undoRedoService.ts`**
   - Audit existing `popUndoAsync` (line 106), `popRedoAsync` (line 138), `clearScope` (line 178), and `isTextInput` (line 222):
     - Confirm `popUndoAsync`/`popRedoAsync` keep `executingLock` active until promise settlement and restore the popped action back onto the original stack if `action.undo()`/`action.redo()` returns `false` or rejects.
     - Add an optional `onWorkspaceReconcile` callback hook / event emitter (`EVENT_WORKSPACE_UNDO_RECONCILE = 'engine-workspace-undo-reconcile'`) carrying `{ nextPages?: PageRegistry; deletedPageIds?: string[]; affectedPageIds?: string[]; updatedCanvases?: Record<string, NodeCanvasDocument> }`.
   - Export `WorkspaceUndoSnapshot`:
     ```ts
     export interface WorkspaceUndoSnapshot {
       canvases?: Record<string, NodeCanvasDocument>;
       pages?: PageRegistry;
       deletedPageIds?: string[];
     }
     ```
   - Export `createWorkspaceUndoAction(params: { type: UndoActionType; description: string; before: WorkspaceUndoSnapshot; after: WorkspaceUndoSnapshot; getLockToken: () => string | null; getExpectedUpdatedAt?: () => string | null; onError?: (msg: string) => void }): Omit<UndoAction, 'id' | 'timestamp'>`:
     - Deep-clones `before` and `after` at creation time so subsequent mutations can never corrupt stored snapshots.
     - `undo()` calls `commitDraftWorkspaceTransaction(before, { lockToken: getLockToken(), expectedUpdatedAt: getExpectedUpdatedAt?.() })`, dispatches `EVENT_DRAFT_CANVAS_CHANGE` for each canvas in `before.canvases`, dispatches `EVENT_DRAFT_PAGES_CHANGE` / `EVENT_DRAFT_CONTENT_CHANGE` if `before.pages` is defined, and emits `EVENT_WORKSPACE_UNDO_RECONCILE` with `{ nextPages: before.pages, deletedPageIds: before.deletedPageIds }`. Returns `true` on success; on error calls `onError?.(msg)` and returns `false` (so `UndoRedoManager.popUndoAsync` automatically rolls back the stack!).
     - `redo()` mirrors the exact same flow using `after`.

2. **Harden `src/context/UndoRedoContext.tsx`**
   - Subscribe to Dev Mode lifecycle & history restore/publish:
     - When `isDevMode` transitions `true -> false` (read safely via optional `useDeveloperMode` or `EVENT_DRAFT_STATUS_CHANGE` with `isActive: false`) OR when `EVENT_HISTORY_CHANGE` fires (after snapshot restore or publish), automatically call `clearHistory()` so stale pre-restore/pre-publish commands can never corrupt the new baseline.
   - Guard keyboard shortcuts (`Cmd+Z`, `Ctrl+Z`, `Cmd+Shift+Z`, `Ctrl+Shift+Z`, `Ctrl+Y`):
     - Only trigger when `isDevMode` is active (never intercept public reader keyboard shortcuts) and `!isTextInput(e.target)`.

3. **Wire Automatic Route Reconciliation in `src/App.tsx` (or dedicated `useWorkspaceRouteReconciler` inside `use-hash-route.ts`)**
   - Listen to `EVENT_WORKSPACE_UNDO_RECONCILE`:
     - Read currently active `activePageId` and `ancestors` (stored in refs to avoid stale closures).
     - **Case 1 — Currently viewed subpage was deleted by undo/redo** (`deletedPageIds?.includes(activePageId)` or `nextPages && activePageId && !isRootChapter(activePageId) && !nextPages[activePageId]`):
       - Walk `ancestors` backwards to find the nearest surviving ancestor (`nextPages[a.id]` or root chapter), and call `navigateToPage(survivingAncestor.id, { replace: true, pagesOverride: nextPages })` (or `navigateToHome()` if none).
       - Show calm toast via `showToast("Returned to <Parent> after undo.", "info")`.
     - **Case 2 — Slug changed on active page or an ancestor** (e.g., undoing a page rename/slug change):
       - Compute `expectedPath = buildPagePath(activePageId, nodes, nextPages, engineConfig.basePath)`.
       - If `window.location.pathname !== expectedPath`, call `navigateToPage(activePageId, { replace: true, pagesOverride: nextPages })` so the address bar never drifts out of sync with the tree!

4. **Migrate `src/hooks/useDocumentCanvas.ts` to Workspace-Addressed Commands**
   - **Remove lines 328–333** (`useEffect(() => () => clearScope(canvasScope), ...)`) so navigating from Page A to Page B preserves Page A's undo history!
   - Update `mutate(...)` (line 340) to accept an optional `undoMeta?: { type: UndoActionType; description: string }` (or return `{ ok, prevDoc, nextDoc, error }`):
     - Inside `addSection`, `addSubsection`, `addElement`, `moveItem`, `relocateItem`, `removeItem`, `updateItem`:
       - Compute `prevDoc` and `nextDoc` cleanly, persist via `mutate`, and ONLY when `res.ok === true`, push a **self-contained workspace-addressed undo action** (`createWorkspaceUndoAction({ type, description, before: { canvases: { [nodeId]: prevDoc } }, after: { canvases: { [nodeId]: nextDoc } }, ... })`) instead of calling mounted-hook `restoreSection` / `removeItem` / `updateItem` closures!
     - Important: If the user is currently on Page B and presses `Cmd+Z`, Page A's `prevDoc` is persisted to `PUT /api/draft` (`canvases: { [pageA]: prevDoc }`) without needing Page A's `useDocumentCanvas` hook to be mounted; when they navigate back to Page A, `GET /api/draft` loads the exact undone AST. And if they ARE on Page A, `EVENT_DRAFT_CANVAS_CHANGE` updates `useDocumentCanvas`'s `document` state immediately!

## 🛡️ Architectural & UI/UX Guardrails

- **No Stale Optimistic Concurrency**: Cross-page undo commands MUST read the **latest** authoritative `draftUpdatedAt` at execution time (`getLastKnownDraftUpdatedAt()`), NEVER a frozen timestamp captured when the original edit occurred.
- **No Unmounted React State Warnings**: Workspace commands must communicate back to mounted hooks strictly via CustomEvents (`EVENT_DRAFT_CANVAS_CHANGE`, `EVENT_DRAFT_PAGES_CHANGE`, `EVENT_WORKSPACE_UNDO_RECONCILE`), never calling `setState` on an unmounted component.
- **Re-entrancy Safety**: Never push a new undo entry while `undoRedoService.isExecuting()` is `true`.
