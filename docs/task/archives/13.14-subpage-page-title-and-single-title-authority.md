## 🎯 Purpose & Scope

Enforce **Single Title & Summary Authority** (`13-PRD.md` Decision #4c) on dynamic subpage headers so the subpage `<PageTitle>`, its parent's `<CanvasPageLink>` card, `<Breadcrumb>`, and `<AppHeader>` dropdown NEVER drift out of sync:
1. Bind dynamic subpage `<PageTitle>` directly to `PageNode` (`title` and `summary`) instead of disconnected `contentOverrides` keys (`node.${id}.title`).
2. Compute calm editorial subpage header defaults:
   - Inherit `accentColor` from the root chapter (`EngineConfig.nodes`).
   - Display the **parent page's title** (or ancestor kicker trail, e.g., `CHAPTER 1` for Level 2, `CHAPTER 1 / RESEARCH` for Level 3) as the default non-ContentDB kicker.
3. Wire `<PageTitle>`'s uniform **`✎ Edit`** button on dynamic subpages to read and write the **exact same `PageNode` record** in `draft.pages` (recording a workspace-level undo command via `createWorkspaceUndoAction`), while preserving existing `contentOverrides` editing untouched on root chapters!

### Step-by-Step Implementation Blueprint

1. **Extend `PageTitleProps` in `src/components/ui/PageTitle.tsx`**
   - Inspect `src/components/ui/PageTitle.tsx` (lines 6–95). Currently, `PageTitle` delegates editing to `<EditableText pointId={...} />`, which always writes to `PortalChromeContext.contentOverrides`.
   - Add optional direct-binding callbacks for single-authority entities (like `PageNode`) while keeping all existing `pointId` props 100% backward compatible:
     ```ts
     /** Direct save handler for title when backed by an external SSOT record (e.g. PageNode) instead of ContentDB */
     onSaveTitle?: (newTitle: string) => void | Promise<void>;
     /** Direct save handler for subtitle/summary when backed by an external SSOT record */
     onSaveSubtitle?: (newSubtitle: string) => void | Promise<void>;
     /** Optional intercept callback to open a unified metadata modal (e.g. PageNode edit modal) on ✎ Edit */
     onEditTitle?: () => void;
     /** Optional intercept callback for subtitle ✎ Edit */
     onEditSubtitle?: () => void;
     ```
   - When `onEditTitle` or `onSaveTitle` is provided (without `titlePointId`):
     - In Public Mode or non-desktop: render clean `<h1 className={styles.title}>{title}</h1>` (zero wrapping DOM overhead).
     - In Dev Mode desktop: wrap `<h1>` in `<DevActionAffordance type="text" currentValue={title} defaultValue={title} onEditText={onEditTitle} onSave={onSaveTitle ? (val) => { void onSaveTitle(val); } : undefined}>` so it displays the **exact uniform `✎ Edit` button** (`editorial-restraint.md` §7 — strictly `"Edit"`, zero custom labels) without writing a single byte to `contentOverrides`!
   - Mirror the exact same pattern for `subtitle` with `onEditSubtitle` / `onSaveSubtitle` (showing an empty-state `✎ Edit` affordance in Dev Mode desktop even when `pageNode.summary` is currently empty so editors can add a summary right from the subpage header!).
   - Keep `kicker` clean and non-overridden on subpages (derived automatically from parent/ancestor titles so renaming a parent chapter or parent subpage immediately updates child kickers automatically!).

2. **Wire Subpage `<PageTitle>` Binding & `PageNode` Save Handler in `src/App.tsx`**
   - Compute subpage default kicker from `ancestors`:
     - On a Level 2 subpage (`ancestors = [rootChapter, subpage]`): `subpageKicker = resolvedNodeTitle` (e.g. `"Access"`).
     - On a Level 3+ subpage (`ancestors = [rootChapter, ..., parent, current]`): `subpageKicker = `${resolvedNodeTitle} / ${parentAncestor.title}`` (e.g. `"Access / Research"`).
   - Implement `handleUpdateSubpageMetadata(targetPageId: string, updates: { title?: string; summary?: string })`:
     - Capture `beforePages = portalChrome.pages`.
     - Validate non-empty `title` (if provided) and `countSummaryWords(updates.summary) <= MAX_PAGE_SUMMARY_WORDS` (showing calm error toast if exceeded).
     - Call `updatePageNodeMetadata(beforePages, targetPageId, updates)` -> `{ pages: nextPages }`.
     - Commit via `await portalChrome.commitWorkspaceMutation({ pages: nextPages })`.
     - Push **one workspace undo command** (`createWorkspaceUndoAction({ type: 'page_update_metadata', description: \`Edit page "${nextPages[targetPageId].title}"\`, before: { pages: beforePages }, after: { pages: nextPages }, ... })`) and call `setHasUnpublishedChanges(true)`.
   - In `src/App.tsx` lines 276–286:
     - **If `isSubpage && pageNode`**:
       ```tsx
       <PageTitle
         kicker={subpageKicker}
         title={pageNode.title}
         subtitle={pageNode.summary}
         accentColor={effectiveAccentColor}
         onSaveTitle={(newTitle) => handleUpdateSubpageMetadata(pageNode.id, { title: newTitle.trim() })}
         onSaveSubtitle={(newSummary) => handleUpdateSubpageMetadata(pageNode.id, { summary: newSummary.trim() || undefined })}
       />
       ```
       *(Zero `titlePointId` / `subtitlePointId` / `kickerPointId` passed for subpages — guarantees `contentOverrides` is NEVER polluted!)*
     - **If root chapter (`!isSubpage && currentNode`)**: keep the exact existing `PageTitle` wiring with `kickerPointId`, `titlePointId`, `subtitlePointId` unchanged.

## 🛡️ Architectural & UI/UX Guardrails

- **Single Title Authority**: Subpage `title` and `summary` MUST NEVER be duplicated into `contentOverrides`; `draft.pages[subpageId]` is the sole source of truth.
- **Uniform `✎ Edit` Standard (`editorial-restraint.md` §7)**: Edit buttons on `<PageTitle>` MUST read strictly `"Edit"` (never `"Edit Subpage Title"`).
- **Word-Budget Guardrail**: Enforcing `<= 15 words` on `summary` edits from `<PageTitle>` keeps card rows on parent canvases clean and single-line.
