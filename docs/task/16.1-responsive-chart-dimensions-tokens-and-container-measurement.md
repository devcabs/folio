## Objective

Establish the design tokens, container width measurement hook, and responsive SVG layout utilities in `src/utils/chartDimensions.ts` so all 5 chart visualizers can render at true container-matched SVG coordinates on `320px–480px` mobile viewports instead of shrinking a fixed `800×360` `viewBox` down to `0.3075×–0.5075×`.

---

## Scope & Exact File Changes

### 1. Design System Tokens (Token Gate First)
- **[src/styles/tokens.css](file:///Users/francisdave/Documents/folio/src/styles/tokens.css)**:
  - Add semantic mobile chart tokens (reusing existing spacing/typography/surface variables where possible — zero hardcoded hex/rgba in component CSS modules):
    - `--chart-pad-surface-mobile`: compact horizontal/vertical card padding on `<= 640px` (e.g., `var(--space-3)` / `12px`).
    - `--chart-axis-font-size-mobile`: minimum readable SVG axis font size (`11px` / `var(--text-xs)` floor, replacing the destructive `8px` shrink).
    - `--chart-value-font-size-mobile`: minimum readable SVG data/value label size (`10px–11px`).
    - `--chart-legend-pill-min-height`: compact touch-friendly mobile legend pill height (e.g., `32px`, preventing `44px` `reset.css` vertical bloat).
    - `--chart-donut-others-fill`: accessible muted slice fill with sufficient contrast against `var(--bg-surface)` for the `"Others"` rollup slice.

### 2. Container Measurement Hook
- **`src/hooks/useChartContainerWidth.ts`** *(new lightweight hook)*:
  - Observes a container `RefObject<HTMLElement | null>` via `ResizeObserver` (with graceful SSR / happy-dom fallback to a sensible default width such as `800` when `ResizeObserver` is unavailable or width is `0`).
  - Returns `{ containerRef, width, isCompact }` where `isCompact = width > 0 && width < 480`.
  - Avoids excessive re-renders by rounding measured width to integer pixels and skipping state updates when unchanged.

### 3. Responsive `chartDimensions.ts` Utilities
- **[src/utils/chartDimensions.ts](file:///Users/francisdave/Documents/folio/src/utils/chartDimensions.ts)**:
  - Ensure `useChartPlotArea()` cleanly supports responsive `width`, `height`, and `isCompact` inputs (with sensible mobile height defaults so charts don't collapse to `110px` tall at `320px`, e.g., minimum mobile height `240px–280px` for Cartesian charts).
  - **Fix `160` vs `180` Left-Margin Cap Mismatch:** Align `chartDimensions.ts:49-51` (`Math.min(160, ...)`) with `BarChart.tsx:61` (`Math.min(180, ...)`) via a single shared constant and compact-aware mobile cap (so horizontal labels don't starve the plot area at `320px`).
  - **Add Shared Dynamic Y-Tick Left Margin Helper (`computeDynamicLeftMargin`):** Estimates required left margin from formatted Y-tick strings (e.g., `"1,500,000"`) + optional `yLabel` presence + `isCompact`, preventing 6–7 digit Y-ticks from colliding with `yLabel` across all Cartesian charts.
  - **Add Shared X-Tick Decimation Helper (`getVisibleTickIndices` / `computeTickStep`):** Given total category count, plot width, and minimum label width (`~44px–56px` on mobile), returns the stride/indices to render so X-axis ticks never collide on 12+ category mobile charts.
