## 🎯 Purpose & Scope

Eliminate the dangerous "Wrong Data" fallback trap in `src/hooks/useSheetChartData.ts` where unconfigured or missing chart elements silently adopt the data and visualization of unrelated sibling charts on the same node.

In Folio Engine, when an author adds a new chart block to a canvas (or when a chart's ID does not match any pre-baked entry), the system must honestly represent that the chart is pending data configuration. It must **never** substitute arbitrary data from a different indicator simply to avoid showing an empty state.

---

## 🔍 Problem Statement

In `src/hooks/useSheetChartData.ts` (lines 148–153):
```ts
    const matchedBaked = bakedCharts.find((c) => c.chartId === chartId);
    if (matchedBaked) {
      return applyConfigToDataset(matchedBaked, cachedConfig);
    }
    if (nodeId) {
      const nodeBaked = bakedCharts.find((c) => c.nodeId === nodeId);
      if (nodeBaked) {
        return applyConfigToDataset(nodeBaked, cachedConfig);
      }
    }
    return null;
```

### The Failure Mode:
1. An author adds a new indicator chart with an auto-generated ID (e.g. `chart-access-lw09x`).
2. The chart has not yet been linked to an official Google Sheet or pre-baked dataset.
3. `useSheetChartData` searches for `c.chartId === chartId` and finds nothing.
4. It falls through to `bakedCharts.find((c) => c.nodeId === nodeId)`.
5. It grabs the first chart matching `nodeId === 'access'` (for example, "Student Enrollment by Grade Level").
6. The UI renders the title, bars, categories, and metrics of "Student Enrollment" in a card intended for a completely different indicator!
7. The visitor or coordinator is presented with counterfeit data masquerading as the new indicator.
