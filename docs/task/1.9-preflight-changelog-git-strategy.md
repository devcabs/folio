## 🎯 Purpose & Scope

Establish the definitive strategy for how `CHANGELOG.md` is generated, verified, and excluded from source control — before `generate-changelog.ts` is built in task 1.14. Auto-generated files in source create PR noise, merge conflicts, and a false source-of-truth split between `ledger.ts` (the actual truth) and `CHANGELOG.md` (a stale derivative). This task defines the generation flags, CI verification hook, and `.gitignore` contract upfront so task 1.14 can implement them without ambiguity.

---

## 🔍 Problem Statement

Task 1.14 plans to compile `CHANGELOG.md` and commit it to git as part of the deploy script. Auto-generated files committed to source are problematic: they appear as noise in every PR diff, cause merge conflicts if two branches bump versions simultaneously, and create a false "source of truth" split between `ledger.ts` (the actual truth) and `CHANGELOG.md` (a derivative that can go stale). The strategy must be defined before the generate-changelog script is built.

## 📄 Key Files to Create / Modify

1. **`.gitignore`** *(Modify)*
   - Add `CHANGELOG.md` on its own line with a comment:
     ```gitignore
     # Auto-generated from src/migrations/ledger.ts at publish time — do not commit.
     CHANGELOG.md
     ```
   - Verify that any existing `CHANGELOG.md` file is now untracked after this change (`git status` should show it as untracked/ignored, not modified).

2. **`scripts/generate-changelog.ts`** *(Pre-wire for 1.14)*
   - Establish the CLI interface contract that task 1.14 must implement. Create the file now with the flag parsing and dispatch logic, leaving the actual changelog generation body as a stub:
     - `--output <path>` flag: Write generated changelog to this path. Defaults to `./CHANGELOG.md`.
     - `--dry-run` flag: Print generated changelog to stdout only. Do NOT write to disk.
     - `--verify` flag: Generate changelog in memory, read existing file at `--output` path, diff them, and:
       - Exit `0` if identical.
       - Exit `1` and print a human-readable diff summary if they differ.
   - Parse flags using `process.argv` (no external flag-parsing library).
   - Stub the `generateChangelog(): string` function that task 1.14 will implement:
     ```ts
     function generateChangelog(): string {
       // TODO (task 1.14): Import FOLIO_MIGRATION_LEDGER and format CHANGELOG.md
       return '';
     }
     ```

3. **`package.json`** *(Modify)*
   - Add two scripts:
     ```json
     "changelog": "tsx scripts/generate-changelog.ts",
     "changelog:verify": "tsx scripts/generate-changelog.ts --verify"
     ```
   - Confirm `CHANGELOG.md` is NOT listed in the `"files"` field (since only `dist` and `bin` are listed, it is already excluded from the npm package — add an inline comment documenting this explicitly):
     ```json
     "files": ["dist", "bin"]
     ```

4. **`.github/workflows/`** *(New or Modify — if CI exists)*
   - If a GitHub Actions workflow file exists (`ci.yml`, `main.yml`, or similar):
     - Add a CI step to the PR workflow:
       ```yaml
       - name: Verify changelog is current
         run: npm run changelog:verify
       ```
   - If no CI workflow file exists:
     - Create `docs/task/ci-changelog-verification.md` documenting the recommended CI step for consumer apps:
       ```md
       # CI: Changelog Verification

       Add this step to your CI workflow on PRs targeting `main`:

       ```yaml
       - name: Verify changelog is current
         run: npx folio-engine changelog --verify
       ```

       This step fails if `ledger.ts` has entries not reflected in `CHANGELOG.md`.
       ```
