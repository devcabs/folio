## 🎯 Purpose & Scope

Enforce that `FOLIO_MIGRATION_LEDGER` is validated at runtime using Zod at the moment the module is imported, not just at compile time. TypeScript's structural checking cannot catch runtime mutations, `v`-prefixed version strings, or `null` values where arrays are expected. By validating on module load, the entire runtime is protected from malformed ledger data the moment the library is consumed.

---

## 🔍 Problem Statement

`FOLIO_MIGRATION_LEDGER` is a TypeScript-typed array, but TypeScript's structural checking won't catch runtime mutations, JSON imports, or cases where a developer adds an entry with `version: 'v0.1.4'` (note the `v` prefix) or `breakingChanges: null` instead of `[]`. Semver comparisons and deploy gate checks then silently produce wrong results. The Zod schemas defined in task 1.10 must actually be used to validate the ledger at module load time.

---

## 📄 Key Files to Create / Modify

1. **`src/types/migration.ts`** *(Pre-wire for 1.10)*
   - All type definitions must be backed by named Zod schema exports (not just TypeScript interfaces):
     - `ContentMigrationSchema = z.object({ ... })` with `.strict()`.
     - `CodeMigrationSchema = z.object({ ... })` with `.strict()`.
     - `MigrationEntrySchema = z.object({ ... })` with:
       - `version`: validated against `/^\d+\.\d+\.\d+(-[a-zA-Z0-9.-]+)?$/` using `z.string().regex(...)` — the `v` prefix is explicitly disallowed.
       - `breakingChanges`: `z.array(z.string()).default([])` — `null` or `undefined` coerces to `[]`.
       - `codeActions`: `z.array(CodeMigrationSchema).default([])`.
       - `contentChanges`: `z.array(ContentMigrationSchema).default([])`.
     - `PendingMigrationReportSchema = z.object({ ... })`.
   - Derive TypeScript types from schemas using `z.infer<typeof XSchema>`:
     ```ts
     export type MigrationEntry = z.infer<typeof MigrationEntrySchema>;
     export type ContentMigration = z.infer<typeof ContentMigrationSchema>;
     ```
   - Export both the Zod schemas AND the inferred types.

2. **`src/migrations/ledger.ts`** *(Pre-wire for 1.11)*
   - Define the raw ledger data as a private, unexported constant:
     ```ts
     const _RAW_LEDGER = [ /* ... entries ... */ ];
     ```
   - Immediately validate on module load using `safeParse`:
     ```ts
     const _validation = z.array(MigrationEntrySchema).safeParse(_RAW_LEDGER);
     if (!_validation.success) {
       throw new Error(
         `[folio-engine] FOLIO_MIGRATION_LEDGER is malformed:\n${_validation.error.message}`
       );
     }
     export const FOLIO_MIGRATION_LEDGER: MigrationEntry[] = _validation.data;
     ```
   - **Only the validated, Zod-parsed data is exported.** The raw `_RAW_LEDGER` array is NEVER exported.
   - The `throw` on invalid data ensures the entire consuming application fails loudly at startup — not silently at some later comparison point.
