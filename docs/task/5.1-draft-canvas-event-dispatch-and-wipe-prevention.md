## 🎯 Purpose & Scope

Eliminate the screen wipe and event deafness that prevents active canvas views from reflecting newly initialized or newly published draft states:
1. **Dispatch Canvas Changes on Draft Initialization:** In `src/services/draftService.ts#initDraftSession()`, dispatch `EVENT_DRAFT_CANVAS_CHANGE` via `dispatchAggregateCanvasChange(true)` immediately after `inMemoryDraftCanvases` is populated.
2. **Dispatch Canvas Changes on Publish Sync:** In `src/services/draftService.ts#syncDraftWithPublished()`, invoke `dispatchAggregateCanvasChange(true)` and synchronize draft content overrides via `setAllContentOverrides(contentOverrides, true)`.
3. **Prevent Premature Screen Wipe in `useDocumentCanvas`:** When `isDevMode` toggles from `false` to `true`, do not overwrite React's active `document` state with an empty `createDefaultCanvasDocument(nodeId)` if `inMemoryDraftCanvases` is pending hydration; preserve the existing rendered document until the draft is ready.

## 🔍 Problem Statement

1. **The Event Deafness Bug:** In [useDocumentCanvas.ts#L131-L146](file:///Users/francisdave/Documents/folio/src/hooks/useDocumentCanvas.ts#L131-L146), the hook subscribes exclusively to `subscribeToCanvasChange(nodeId, callback, isDevMode)` which listens for `EVENT_DRAFT_CANVAS_CHANGE`. When [initDraftSession()](file:///Users/francisdave/Documents/folio/src/services/draftService.ts#L592-L595) completes its asynchronous fetch of published node data, it calls `dispatchDraftChange()`, which emits only `EVENT_DRAFT_STATUS_CHANGE` and `EVENT_DRAFT_CONTENT_CHANGE`. It **never** emits `EVENT_DRAFT_CANVAS_CHANGE`. React components remain permanently stuck on whatever state was returned before the network call resolved.
2. **The Dev Mode Toggle Wipe:** When a public visitor viewing live published content enters Developer Mode, `isDevMode` changes from `false` to `true`. [useDocumentCanvas.ts#L126](file:///Users/francisdave/Documents/folio/src/hooks/useDocumentCanvas.ts#L126) immediately executes:
   ```ts
   const initialDoc = isDevMode ? getNodeCanvas(nodeId, true) : createDefaultCanvasDocument(nodeId);
   documentRef.current = initialDoc;
   setDocument(initialDoc);
   ```
   Because `initDraftSession` has not yet resolved, `getNodeCanvas(nodeId, true)` returns an empty factory default. This wipes the live content from the screen, replacing it with an empty canvas, and because of problem #1, the screen never updates after the fetch completes.
3. **Post-Publish View Stagnation:** In [draftService.ts#L634-L683](file:///Users/francisdave/Documents/folio/src/services/draftService.ts#L634-L683), `syncDraftWithPublished()` updates `inMemoryDraftCanvases`, but does not call `dispatchAggregateCanvasChange(true)`. The canvas view does not refresh to display the newly published baseline.

## 🏛️ Karpathy Heuristics & Rules

1. **Think Before Coding:**
   - Any asynchronous mutation of `inMemoryDraftCanvases` must notify listening components via the established channel event (`EVENT_DRAFT_CANVAS_CHANGE`).
   - Switching authoring modes should never degrade a currently rendered document to an empty placeholder while asynchronous work is pending.
2. **Make Surgical Changes:**
   - Call `dispatchAggregateCanvasChange(true)` at the completion of `initDraftSession()` and `syncDraftWithPublished()`.
   - Update `useDocumentCanvas` to preserve active document state during mode transitions if the destination draft channel is still hydrating.
3. **Verify Everything:**
   - Test that entering Dev Mode with a mocked delayed edge response preserves the displayed document and updates cleanly once the edge response resolves.

### Step 2: Prevent Premature Screen Wipe in `useDocumentCanvas.ts`

In `src/hooks/useDocumentCanvas.ts`:
Update the `useEffect` handling initial document synchronization:
```ts
  useEffect(() => {
    // If switching into Dev Mode, check if in-memory draft is already populated
    let initialDoc: NodeCanvasDocument;
    if (isDevMode) {
      const memoryDraft = getNodeCanvas(nodeId, true);
      // If draft is still an unpopulated default shell but we already have live content rendered,
      // retain current document until draft initialization completes and emits EVENT_DRAFT_CANVAS_CHANGE
      if (
        memoryDraft.sections.length === 0 &&
        documentRef.current.sections.length > 0 &&
        documentRef.current.nodeId === nodeId
      ) {
        initialDoc = documentRef.current;
      } else {
        initialDoc = memoryDraft;
      }
    } else {
      initialDoc = createDefaultCanvasDocument(nodeId);
    }

    documentRef.current = initialDoc;
    setDocument(initialDoc);

    const unsubscribe = subscribeToCanvasChange(
      nodeId,
      (incomingDoc) => {
        if (incomingDoc.updatedAt === localUpdateTimestampRef.current) {
          return;
        }
        if (
          documentRef.current.updatedAt !== incomingDoc.updatedAt ||
          documentRef.current.sections.length !== incomingDoc.sections.length
        ) {
          documentRef.current = incomingDoc;
          startTransition(() => {
            setDocument(incomingDoc);
          });
        }
      },
      isDevMode
    );

    return unsubscribe;
  }, [nodeId, isDevMode]);
```
