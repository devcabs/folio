## 🎯 Purpose & Scope

Consolidate all engine configuration, active node lists, node metadata keys, and content version watermarks onto a single authoritative source (`EngineConfig`), and lock in the entire Epic 7 Single Source of Truth architecture with a comprehensive automated verification suite (`tests/ssot-invariants.test.ts`):

1. **Single Authoritative Node Registry (`getEngineConfig().nodes`)**:
   - Eliminate runtime fallbacks from `EngineConfig.nodes` to static `src/data/sample-nodes.json`, `src/data/node-nodes.json`, and hardcoded 5-node arrays (`NODE_IDS` / `VALID_NODES` / `NODE_ITEMS`) across `src/App.tsx`, `src/components/roadmap/PhotoFlightEngine.tsx`, `src/components/roadmap/RoadmapTrack.tsx`, `src/components/layout/AppFooter.tsx`, `src/services/historyService.ts`, `src/services/draftService.ts`, `src/services/canvasLayoutService.ts`, and `src/hooks/use-hash-route.ts`.
   - Derive active node IDs, labels, stage numbers, and routes dynamically from `getEngineConfig().nodes` via a single canonical selector (`getActiveNodes()` / `getActiveNodeIds()` in `src/config/engine.config.ts`).
2. **Eliminate Node Metadata Key Collision (`src/App.tsx` vs. `src/components/roadmap/RoadmapNode.tsx`)**:
   - Fix the key collision where `RoadmapNode.tsx` binds `node.summary` to `pointId="node.${page.id}.summary"` while `App.tsx` binds `currentNode.summary` to `subtitlePointId="node.${currentNode.id}.subtitle"`. Both views must consume the identical canonical `pointId` (`node.${id}.summary` for summary, `node.${id}.title` for display title, `node.${id}.kicker` / `node.${id}.tagline` for eyebrow).
3. **Single-Source Content Watermark (`src/utils/watermarkResolver.ts`, `src/diagnostics/migrationDoctor.ts`)**:
   - Resolve the content version watermark strictly from `EngineConfig.contentVersion` (the Consumer application's declared source of truth in code), eliminating the competing `localStorage['folio_content_version']` max-semver override and `persistContentWatermark()` `localStorage` write in `watermarkResolver.ts`.
   - Resolve the engine package version in `migrationDoctor.ts` strictly from `package.json`, failing stop if `package.json` cannot be read instead of falling back to `FOLIO_MIGRATION_LEDGER` or `'0.0.0'`.
4. **End-to-End SSOT Invariant Verification Suite (`tests/ssot-invariants.test.ts`)**:
   - Implement a comprehensive Vitest suite verifying every SSOT invariant across all 10 domains:
     - **Invariant 1 (Live Cloudflare KV Only)**: Static & runtime AST/codebase scan proving zero Supabase references, zero `localStorage` / `sessionStorage` / `IndexedDB` calls, and zero module-level shadow stores (`inMemoryLive*`, `inMemoryDraft*`, `liveMemoryCache`, `draftMemoryCache`, `inMemoryManifest`, `inMemoryRegistry`, `memoryCache`).
     - **Invariant 2 (Self-Contained Document AST)**: Round-trip verification proving `NodeCanvasDocument` embeds `ChartElement.config`, `ChartElement.dataset`, and `GalleryElement.syncedPhotos` directly in the AST across `draft:workspace`, `POST /api/publish` (`node:*`, `history:snapshot:*`), and `POST /api/history/restore`.
     - **Invariant 3 (Strict Fail-Stop)**: Fault-injection tests proving every KV, Google Sheets, and Google Drive read/write failure throws or returns HTTP 4xx/5xx immediately with zero dual writes and zero fallback chains.
