## 🎯 Purpose & Scope

Eliminate Supabase `engine_history`, `IndexedDB` (`historyStorage.ts`), `localStorage` (`_history_manifest`, `_live_active_published_id`, `_active_published_id`), `BroadcastChannel` (`_portal_sync`), and module-level `inMemoryManifest` caches. Establish **Cloudflare KV** (`history:index`, `history:snapshot:${id}`, and immutable versioned `node:${snapshotId}:${nodeId}`) as the sole, atomic revision history ledger and publishing destination:
1. **Cloudflare KV Revision History Schema & Edge Endpoints (`src/edge/handlers/historyHandler.ts`, `src/edge/router.ts`)**:
   - Store each published snapshot as a self-contained `PublishedSnapshot` in Cloudflare KV under `history:snapshot:${snapshotId}` (containing `id`, `schemaVersion`, `title`, `description`, `createdAt`, `authorSessionId`, `canvases`, `contentOverrides`, `summary`).
   - Store the ordered revision index in Cloudflare KV under `history:index` (`{ activeSnapshotId: string, updatedAt: string, entries: HistoryIndexEntry[] }`).
   - Expose Edge KV routes in `src/edge/handlers/historyHandler.ts` and `src/edge/router.ts`:
     - `GET /api/history`: Reads `history:index` from Cloudflare KV (and optionally hydrates requested snapshots). Fails stop with HTTP 503 if `!kv` or returns `{ activeSnapshotId: null, entries: [] }` if uninitialized.
     - `GET /api/history/:snapshotId`: Reads `history:snapshot:${snapshotId}` from Cloudflare KV. Fails stop with HTTP 404 if not found or HTTP 503 if `!kv`.
     - `POST /api/history/restore`: Requires `Authorization: Bearer <lockToken>` verified against `lock:coordinator` in KV (HTTP 401/409 if not held). Supports both historical snapshot restoration and factory baseline reset:
       - If `snapshotId === 'snap-system-baseline'`, constructs clean empty `createDefaultCanvasDocument(nodeId)` for each requested `nodeId` in `body.nodeIds` with `contentOverrides: {}` and writes them into `draft:workspace` (`dirty: true`, `baseSnapshotId: history:index.activeSnapshotId || 'uninitialized'`).
       - Otherwise reads `history:snapshot:${snapshotId}` from Cloudflare KV (failing stop with HTTP 404 if missing) and writes **both** its self-contained `canvases` (including embedded `ChartElement` and `GalleryElement`) **and** its `contentOverrides` directly into `draft:workspace` in Cloudflare KV (`dirty: true`, incrementing `revision`), returning the restored `DraftWorkspacePayload`. Fails stop with HTTP 404/502/503 if the snapshot is missing or KV write fails.
2. **Split-Brain-Safe Versioned KV Publish Handler (`src/edge/handlers/publishHandler.ts`)**:
   - Remove all Supabase `engine_history` `fetch` calls and environment checks (`VITE_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, etc.) from `publishHandler.ts`.
   - Remove sidecar `chart:${chartId}` KV writes (since charts are embedded directly inside `NodeCanvasDocument`).
   - In `POST /api/publish`, require a valid `kv` binding (returning HTTP 503 if `!kv`) and verify `Authorization: Bearer <lockToken>` against `lock:coordinator` in KV (returning HTTP 401/409 if invalid or not held).
   - **Two-Phase Versioned Write Order (Eliminates Partial Publish Split-Brain)**:
     - **Phase A (Stage Immutable Payloads First)**:
       1. Write `history:snapshot:${snapshot.id}` (full self-contained `PublishedSnapshot` preserving `ChartElement.config.sheetUrl` for future rollbacks).
       2. For every `nodeId` in `snapshot.canvases`, compile the public node payload (`compilePublicNodePayload`, which pre-bakes `/api/media/drive/:id` URLs on `PhotoElement` and `GalleryElement.syncedPhotos` and strips `ChartElement.config.sheetUrl`) and write to immutable versioned key **`node:${snapshot.id}:${nodeId}`** (as well as `node:${nodeId}`).
     - **Phase B (Flip Active Pointer Last)**:
       3. Only after **all** Phase A writes succeed, update **`portal:manifest`** (`activeSnapshotId = snapshot.id`, `nodeIds`, `contentOverrides = snapshot.contentOverrides`).
       4. Update **`history:index`** (prepending the new snapshot metadata entry and setting `activeSnapshotId = snapshot.id`).
       5. Update **`draft:workspace`** (`baseSnapshotId = snapshot.id`, `dirty: false`, incrementing `revision`, `canvases = snapshot.canvases`, `contentOverrides = snapshot.contentOverrides`).
     - If any KV write fails in Phase A, `portal:manifest.activeSnapshotId` remains untouched and public visitors continue reading `node:${previousSnapshotId}:${nodeId}` with zero split-brain divergence; `POST /api/publish` fails stop immediately with HTTP 502 `{ success: false, error }`.
3. **Eliminate All Browser, Module & `BroadcastChannel` History Stores (`src/services/historyService.ts`, `src/components/history/HistoryHubModal.tsx`)**:
   - Delete `inMemoryManifest`, `syncLightweightLocalStorage()`, `getLocalFallbackSnapshots()`, `getDefaultSystemBaselineSnapshot()`, `hydrateActiveVersionFromCloud()`, `getActivePublishedId()`, `saveMilestone()`, `triggerAutoSave()`, `restoreUnifiedSnapshot()`, `deleteSnapshot()`, `clearAllHistory()`, `exportHistoryBackupJson()`, `importHistoryBackupJson()`, `syncBroadcastChannel`, `broadcastLiveSync()`, `handleIncomingSyncBroadcast()`, and all `IndexedDB` imports from `src/services/historyService.ts`.
   - `fetchPublishedHistoryFromCloud()` queries `GET /api/history` exclusively and throws on HTTP/network failure so `HistoryHubModal.tsx` renders an explicit error state with a **Retry** button.
   - `restoreSnapshotToDraft(snapshotId, nodeIds, lockToken)` calls `POST /api/history/restore` directly in Cloudflare KV (passing `'snap-system-baseline'` when "Restore to default" is clicked in `HistoryHubModal.tsx`) and fails stop on error.

   - **Why It Violates SSOT**: Resolves the active snapshot ID from 4 `localStorage` keys and a hardcoded default, competing with `portal:manifest.activeSnapshotId` and `history:index.activeSnapshotId` in Cloudflare KV.
