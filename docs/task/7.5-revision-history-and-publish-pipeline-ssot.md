## 🎯 Purpose & Scope

Eliminate Supabase `engine_history`, `IndexedDB` (`historyStorage.ts`), `localStorage` (`_history_manifest`, `_live_active_published_id`, `_active_published_id`), and module-level `inMemoryManifest` caches. Establish **Cloudflare KV** (`history:index` and `history:snapshot:${id}`) as the sole, atomic revision history ledger and publishing destination:
1. **Cloudflare KV Revision History Schema & Edge Endpoints (`src/edge/handlers/historyHandler.ts`, `src/edge/router.ts`)**:
   - Store each published snapshot as a self-contained `PublishedSnapshot` in Cloudflare KV under `history:snapshot:${snapshotId}` (containing `id`, `schemaVersion`, `title`, `description`, `createdAt`, `authorSessionId`, `canvases`, `contentOverrides`, `summary`).
   - Store the ordered revision index in Cloudflare KV under `history:index` (`{ activeSnapshotId: string, updatedAt: string, entries: HistoryIndexEntry[] }`).
   - Expose Edge KV routes in `src/edge/handlers/historyHandler.ts` and `src/edge/router.ts`:
     - `GET /api/history`: Reads `history:index` from Cloudflare KV (and optionally hydrates requested snapshots). Fails stop with HTTP 503 if `!kv` or HTTP 404 if uninitialized.
     - `GET /api/history/:snapshotId`: Reads `history:snapshot:${snapshotId}` from Cloudflare KV. Fails stop with HTTP 404 if not found or HTTP 503 if `!kv`.
     - `POST /api/history/restore`: Atomically reads `history:snapshot:${snapshotId}` from Cloudflare KV and writes its `canvases` and `contentOverrides` directly into `draft:workspace` in Cloudflare KV (marking `dirty: true` and `baseSnapshotId: snapshotId`), returning the restored `DraftWorkspacePayload`. Fails stop with HTTP 404/502/503 if the snapshot is missing or KV write fails.
2. **Atomic Pure-KV Publish Handler (`src/edge/handlers/publishHandler.ts`)**:
   - Remove all Supabase `engine_history` `fetch` calls and environment checks (`VITE_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, etc.) from `publishHandler.ts`.
   - Remove sidecar `chart:${chartId}` KV writes (since charts are embedded directly inside `NodeCanvasDocument` in `node:${nodeId}`).
   - In `POST /api/publish`, require a valid `kv` binding (returning HTTP 503 if `!kv`) and atomically write to Cloudflare KV:
     1. `history:snapshot:${snapshot.id}` (full self-contained `PublishedSnapshot`).
     2. `history:index` (prepending the new snapshot metadata entry and setting `activeSnapshotId = snapshot.id`).
     3. `node:${nodeId}` for every node in `snapshot.canvases` (compiled with self-contained `NodeCanvasDocument`).
     4. `portal:manifest` (setting `activeSnapshotId = snapshot.id` and `contentOverrides = snapshot.contentOverrides`).
     5. `draft:workspace` (updating `baseSnapshotId = snapshot.id`, `dirty: false`, `canvases = snapshot.canvases`, `contentOverrides = snapshot.contentOverrides`).
   - If any KV read or write fails during `POST /api/publish`, fail stop immediately with HTTP 502 `{ success: false, error }`.
3. **Eliminate All Browser & Module History Stores (`src/services/historyService.ts`, `src/components/history/HistoryHubModal.tsx`)**:
   - Remove `inMemoryManifest`, `syncLightweightLocalStorage()`, `getLocalFallbackSnapshots()`, `getDefaultSystemBaselineSnapshot()`, `hydrateActiveVersionFromCloud()`, `getActivePublishedId()` 5-stage `localStorage` fallback chain, and all `IndexedDB` imports from `src/services/historyService.ts`.
   - `fetchPublishedHistoryFromCloud()` queries `GET /api/history` exclusively and throws on HTTP/network failure so `HistoryHubModal.tsx` renders an explicit error state with a **Retry** button.
   - `restoreSnapshotToDraft(snapshotId)` calls `POST /api/history/restore` directly in Cloudflare KV and fails stop on error.

## 🔍 Forensic Audit Findings Addressed

1. **[V5.1] `getActivePublishedId()` 5-Stage `localStorage` Fallback Chain**
   - **Locations**: [historyService.ts](file:///Users/francisdave/Documents/folio/src/services/historyService.ts#L163-L196), [historyService.ts](file:///Users/francisdave/Documents/folio/src/services/historyService.ts#L1431-L1444)
   - **Conflicting Sources / Fallback Chain**: `localStorage` `_live_active_published_id` → `_active_published_id` → `_history_manifest.activePublishedId` → `_history_manifest.activeMilestoneId` → `'snap-system-baseline'`
   - **Why It Violates SSOT**: Resolves the active snapshot ID from 4 `localStorage` keys and a hardcoded default, competing with `portal:manifest.activeSnapshotId` and `history:index.activeSnapshotId` in Cloudflare KV.

2. **[V5.2] Triple Local History Manifest Storage (`inMemoryManifest`, `IndexedDB`, and Stripped `localStorage`)**
   - **Locations**: [historyService.ts](file:///Users/francisdave/Documents/folio/src/services/historyService.ts#L261-L392), [historyStorage.ts](file:///Users/francisdave/Documents/folio/src/services/historyStorage.ts#L71-L132)
   - **Conflicting Sources / Fallback Chain**: `inMemoryManifest` ↔ `IndexedDB` (`history_store`) ↔ `localStorage` (`_history_manifest`, stripped of `canvases` and `contentOverrides`).
   - **Why It Violates SSOT**: Duplicates history across three browser/module stores instead of storing revision history exclusively in Cloudflare KV (`history:index` and `history:snapshot:${id}`).

3. **[V5.3] `fetchPublishedHistoryFromCloud()` & `HistoryHubModal` Supabase + Local Fallback**
   - **Locations**: [historyService.ts](file:///Users/francisdave/Documents/folio/src/services/historyService.ts#L891-L1022), [HistoryHubModal.tsx](file:///Users/francisdave/Documents/folio/src/components/history/HistoryHubModal.tsx#L254-L282)
   - **Conflicting Sources / Fallback Chain**: Supabase `engine_history` → `getLocalFallbackSnapshots()` (`localStorage`/`IndexedDB`/`inMemoryManifest`) → `getDefaultSystemBaselineSnapshot()` (`'snap-system-baseline'`)
   - **Why It Violates SSOT**: Queries Supabase and falls back to browser storage and a fabricated baseline snapshot instead of querying Cloudflare KV (`GET /api/history`) and failing stop on error.

4. **[V5.4] `fetchActivePublishedVersionFromCloud()` & `hydrateActiveVersionFromCloud()` Mirroring Supabase to `localStorage`**
   - **Locations**: [historyService.ts](file:///Users/francisdave/Documents/folio/src/services/historyService.ts#L1027-L1096), [historyService.ts](file:///Users/francisdave/Documents/folio/src/services/historyService.ts#L1457-L1511), [DeveloperModeContext.tsx](file:///Users/francisdave/Documents/folio/src/context/DeveloperModeContext.tsx#L278-L282)
   - **Conflicting Sources / Fallback Chain**: Queries Supabase `engine_history` and mirrors canvases and content overrides into `localStorage` (`_live_canvas_*`, `_live_content_overrides`).
   - **Why It Violates SSOT**: Mirrors Supabase into `localStorage` on Dev Mode entry, competing with Cloudflare KV.

5. **[V5.5] Dual-Backend Server Publish (Supabase + KV) & 10-Way Client Fan-Out**
   - **Locations**: [publishHandler.ts](file:///Users/francisdave/Documents/folio/src/edge/handlers/publishHandler.ts#L104-L240), [historyService.ts](file:///Users/francisdave/Documents/folio/src/services/historyService.ts#L1259-L1315)
   - **Conflicting Sources / Fallback Chain**: Server writes to Supabase `engine_history` + KV `node:*` + KV `chart:*` + KV `portal:manifest`. Client writes to `localStorage` live canvases, `localStorage` live content, `IndexedDB`, `localStorage` history manifest, `localStorage` active ID, and module-level draft memory.
   - **Why It Violates SSOT**: Splits publishing across Supabase, Cloudflare KV, `localStorage`, `IndexedDB`, and module-level caches.

6. **[V5.6] `captureCurrentSnapshot()` & `restoreUnifiedSnapshot()` Reading/Writing `localStorage`**
   - **Locations**: [historyService.ts](file:///Users/francisdave/Documents/folio/src/services/historyService.ts#L540-L573), [historyService.ts](file:///Users/francisdave/Documents/folio/src/services/historyService.ts#L634-L687)
   - **Conflicting Sources / Fallback Chain**: Reads `getLiveNodeCanvas(nodeId)` (`localStorage`) and writes `saveNodeCanvas(canvasDoc, false)` (`localStorage`).
   - **Why It Violates SSOT**: Captures and restores snapshots against browser `localStorage` instead of Cloudflare KV.
