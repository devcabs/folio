## 🎯 Purpose & Scope

Ensure that every Canvas Section (`<CanvasSection>`) in Developer Mode (`isAuthoringActive === true`) renders a `<CanvasAddBar>` (`barId="sec-top-${section.id}"`) immediately after the section's `<SectionTitle as="h2">` heading, regardless of whether `section.elements` is empty or already populated.

---

## 🔍 Problem Statement

In [DocumentCanvas.tsx#L618-L626](file:///Users/francisdave/Documents/folio/src/components/canvas/DocumentCanvas.tsx#L618-L626), the insertion bar at index `0` of a section is currently gated by `(section.elements || []).length === 0`:

```tsx
{/* Section-Level Initial Insertion Dropzone: Only shown when section has no elements */}
{isAuthoringActive && (section.elements || []).length === 0 && (
  <CanvasAddBar
    barId={`sec-top-${section.id}`}
    activeBarId={activeAddBarId}
    onToggleActive={handleToggleAddBarActive}
    onAddElement={(type) => handleAddElement(type, section.id, 0)}
    accentColor={accentColor}
  />
)}
```

Because almost every section on a node canvas contains at least one child element (`section.elements.length > 0`), `(section.elements || []).length === 0` evaluates to `false`. As a result:
- There is **never** an `+ Add Element` bar after a section heading (`Section 01 / ...`) once the section has any child elements.
- Coordinators cannot insert a new text paragraph, photo, gallery, chart, or subsection at the top of an existing section (index `0`, immediately below the section heading).

---

## 🏛️ Karpathy Heuristics & Rules

1. **Think Before Coding:**
   - Verify how `handleAddElement(type, section.id, 0)` behaves for all element types (`text`, `photo`, `gallery`, `chart`, `subsection`, `section`) when `section.elements` already has elements:
     - Leaf elements (`text`, `photo`, `gallery`, `chart`): calls `addElement(section.id, leaf, 0)`, which invokes `insertLeafElement(doc, section.id, leaf, 0)` (`elements.splice(0, 0, element)`), cleanly prepending the leaf at index `0` of the section.
     - `subsection`: calls `restoreSubsection(section.id, newSub, 0)`, which invokes `insertSubsection(doc, section.id, newSub, 0)` (`elements.splice(0, 0, subsection)`), cleanly prepending the subsection at index `0` of the section.
     - `section`: calls `restoreSection(newSec, secIdx + 1)`, inserting a new section after the current section.
2. **Make Surgical Changes:**
   - Remove the `&& (section.elements || []).length === 0` condition on `sec-top-${section.id}` in `src/components/canvas/DocumentCanvas.tsx`.
3. **Verify Everything:**
   - Write unit/component tests confirming that `sec-top-${section.id}` renders in Dev Mode both when `section.elements` is empty and when `section.elements` has children, and remains completely absent in Public Mode (`isDevMode === false`).
