## 🎯 Purpose & Scope

Establish formal TypeScript data contracts and Zod schemas for tracking version transitions, breaking changes, required code actions, and pending content migrations. Extend `EngineConfig` so consumer applications can declare their content watermark.

---

## 📄 Key Files to Create / Modify

1. **`src/types/migration.ts`** *(New)*
   - Define TypeScript interfaces:
     - `ContentMigration`:
       - `id: string`
       - `title: string`
       - `required: boolean`
       - `description: string`
       - `affectedEntities?: string[]` (e.g. `["nodes", "sample-nodes.json", "chartDatasets"]`)
       - `migrationPrompt?: string` (Actionable instructions for an AI assistant to execute)
     - `CodeMigration`:
       - `description: string`
       - `affectedFiles?: string[]`
       - `exampleBefore?: string`
       - `exampleAfter?: string`
     - `MigrationEntry`:
       - `version: string` (Semver string, e.g. `'0.1.3'`)
       - `releaseDate: string` (ISO format or YYYY-MM-DD)
       - `title: string`
       - `summary: string`
       - `breakingChanges: string[]`
       - `codeActions: CodeMigration[]`
       - `contentChanges: ContentMigration[]`
     - `PendingMigrationReport`:
       - `currentEngineVersion: string`
       - `contentVersionWatermark: string`
       - `hasPendingContentChanges: boolean`
       - `pendingContentChanges: ContentMigration[]`
       - `unappliedVersions: string[]`

2. **`src/config/engine.config.ts`** *(Modify)*
   - Add `contentVersion?: z.string().optional()` to `EngineConfigSchema`.
   - Add `contentVersion?: string` to `EngineConfig` interface.
   - Default `contentVersion` in `createDefaultEngineConfig` to fallback or current package version.

3. **`src/index.ts`** *(Modify)*
   - Export all types from `./types/migration`.
