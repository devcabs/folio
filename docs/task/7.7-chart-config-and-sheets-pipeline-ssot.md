## 🎯 Purpose & Scope

Eliminate `src/services/chartSourceService.ts` (Supabase `chart_sources`, module-level `memoryCache`, `localStorage` `_chart_source_*` and `_chart_sources_manifest`), `localStorage` `chart_matrix_*`, static `src/data/baked-charts.json` fallbacks, duplicate `ChartCard` sync paths, and multi-tier scraping fallbacks. Embed all chart configurations and datasets directly inside `ChartElement` on the `NodeCanvasDocument` AST stored in Cloudflare KV:
1. **Self-Contained `ChartElement` in Canvas AST (`src/types/canvas.ts`, `src/hooks/useSheetChartData.ts`, `src/components/canvas/CanvasChart.tsx`)**:
   - Every `ChartElement` in `NodeCanvasDocument` directly carries `config?: SheetChartConfig` and `dataset?: ChartDataset`.
   - **Public Mode (`isDevMode = false`)**: `CanvasChart` / `useSheetChartData` renders strictly from `element.dataset` and `element.config` hydrated on the `NodeCanvasDocument` from `GET /api/public/node/:nodeId`. Zero Supabase queries, zero `/api/public/chart/:id` requests, zero `localStorage` reads/writes, zero module-level `memoryCache`, and zero fallback to `src/data/baked-charts.json`.
   - **Dev Mode (`isDevMode = true`)**: `CanvasChart` / `ChartConfigDrawer` reads `element.config` and `element.dataset` from the active `NodeCanvasDocument` in `draft:workspace`. When a coordinator configures a chart or triggers a live Google Sheets sync, the compiled `SheetChartConfig` and `ChartDataset` are written directly into the `ChartElement` on the `NodeCanvasDocument` AST and persisted to Cloudflare KV `draft:workspace` via `PUT /api/draft`.
2. **Eliminate `src/services/chartSourceService.ts` & Fail-Stop on Save (`src/components/chart/ChartConfigDrawer.tsx`)**:
   - Delete `src/services/chartSourceService.ts` (eliminating `memoryCache`, `localStorage` `_chart_source_*`, Supabase `chart_sources`, and `__cached_dataset` / `__node_id` shadow columns).
   - In `ChartConfigDrawer.tsx`, saving a chart configuration updates the `ChartElement` in the `NodeCanvasDocument` AST and awaits `PUT /api/draft` to Cloudflare KV. If `PUT /api/draft` fails, fail stop: keep `ChartConfigDrawer` open and display the error banner.
3. **Deduplicate Live Sheet Sync & Fail-Stop on Fetch/Parse Error (`src/components/chart/ChartCard.tsx`, `src/services/sheetsDataService.ts`, `src/components/chart/drawer/hooks/useLiveMatrixSync.ts`)**:
   - Remove the duplicate `fetchLiveSheetMatrix` → `saveChartConfigDetailed` implementation in `ChartCard.tsx`; delegate exclusively to `onSync` (which fetches the live matrix, compiles the `ChartDataset`, and updates the `ChartElement` in `draft:workspace` via `PUT /api/draft`).
   - Make `fetchLiveSheetMatrix()` throw an explicit `Error` on invalid URL, non-2xx HTTP status, HTML login redirect, or network timeout instead of returning `[]`.
   - In `useLiveMatrixSync.ts`, propagate errors from `fetchLiveSheetMatrix()` and do not fall back to `previewMatrix` when a live fetch fails.
4. **Single-Source Google Sheets Verification (`src/services/sheetsVerificationService.ts`)**:
   - Remove the multi-tier fallback from Google Sheets API v4 to `/htmlview` regex scraping and hardcoded `'Sheet1'`.

1. **[V7.1] Chart Config Sidecar Service, Module `memoryCache`, `localStorage`, Supabase `chart_sources`, & Intra-Row Shadow Fields**
   - **Locations**: [chartSourceService.ts](file:///Users/francisdave/Documents/folio/src/services/chartSourceService.ts#L63), [chartSourceService.ts](file:///Users/francisdave/Documents/folio/src/services/chartSourceService.ts#L113-L259), [useChartConfigForm.ts](file:///Users/francisdave/Documents/folio/src/components/chart/drawer/hooks/useChartConfigForm.ts#L450-L508)
   - **Conflicting Sources / Fallback Chain**: `memoryCache` ↔ `localStorage` (`_chart_source_${id}`, `_chart_sources_manifest`) ↔ Supabase `chart_sources` (`cached_dataset` + `visual_config.__cached_dataset`, `node_id` + `visual_config.__node_id`).
   - **Why It Violates SSOT**: Stores chart configs outside the Canvas AST across module memory, `localStorage`, and Supabase `chart_sources`.

2. **[V7.2] `fetchChartConfig()` & `fetchChartConfigsByNode()` Silent Local Cache Fallback**
   - **Locations**: [chartSourceService.ts](file:///Users/francisdave/Documents/folio/src/services/chartSourceService.ts#L264-L375)
   - **Conflicting Sources / Fallback Chain**: `getCachedChartConfig` → Supabase `chart_sources` → fallback to `getCachedChartConfig` / `localStorage` manifest on error.
   - **Why It Violates SSOT**: Queries Supabase and silently returns stale browser/module cache when Supabase fails instead of reading `ChartElement` from the Canvas AST.

3. **[V7.3] `saveChartConfigDetailed()` Dual Write, Schema-Stripping Retry, & Local-Only Success**
   - **Locations**: [chartSourceService.ts](file:///Users/francisdave/Documents/folio/src/services/chartSourceService.ts#L414-L619), [ChartConfigDrawer.tsx](file:///Users/francisdave/Documents/folio/src/components/chart/ChartConfigDrawer.tsx#L333-L347), [ChartConfigDrawer.tsx](file:///Users/francisdave/Documents/folio/src/components/chart/ChartConfigDrawer.tsx#L406-L421)
   - **Conflicting Sources / Fallback Chain**: Writes `localStorage` before Supabase, strips rejected columns on HTTP 400, and returns `success: savedLocally` (`true`) even when Supabase fails.
   - **Why It Violates SSOT**: Treats a failed persistence call as a success if `localStorage` succeeded.
