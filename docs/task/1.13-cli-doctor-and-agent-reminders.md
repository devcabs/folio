## 🎯 Purpose & Scope

Provide automated, terminal-accessible tooling so that AI agents (and human engineers) working in consumer repositories can audit compatibility, identify breaking code/content changes, and receive immediate step-by-step migration instructions.

---

## 📄 Key Files to Create / Modify

1. **`src/diagnostics/migrationDoctor.ts`** *(New)*
   - Node-compatible diagnostic routine:
     - Inspects consumer project's `package.json` for installed `@devcabs/folio-engine` version.
     - Inspects local config / content files if present (`sample-nodes.json`, `src/engine-setup.ts`, etc.).
     - Compares versions against `FOLIO_MIGRATION_LEDGER`.
     - Formats clean terminal output with ANSI colors and markdown blocks:
       - 📦 Version comparison (Installed vs Latest Available).
       - 🚨 Breaking code/config changes with code examples (before/after).
       - 📝 Required pending content changes.
       - 🤖 Agent Prompt Block: Ready-to-execute instructions for the AI assistant.

2. **`bin/folio-engine.js`** *(New Executable)*
   - Standalone CLI runner with Shebang (`#!/usr/bin/env node`).
   - Supports:
     - `npx folio-engine doctor` or `npx folio-engine check`
     - `npx folio-engine changelog`
     - `npx folio-engine version`

3. **`package.json`** *(Modify)*
   - Add `"bin": { "folio-engine": "./bin/folio-engine.js" }`.
   - Add `"files": ["dist", "bin"]`.
   - Add scripts: `"doctor": "tsx src/diagnostics/migrationDoctor.ts"`.

4. **`.agents/rules/folio-engine-migration.md`** *(New)*
   - Reusable agent rule that can be copied or imported by consumer applications.
   - Instructs the AI:
     > *"Whenever `@devcabs/folio-engine` is upgraded, run `npx folio-engine doctor` first. Review all breaking changes and required pending content changes before making code modifications."*
