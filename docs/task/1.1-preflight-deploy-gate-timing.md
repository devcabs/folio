## 🎯 Purpose & Scope

Prevent orphan git version tags by computing the target semver BEFORE `npm version` is ever called. Task 1.14 adds a ledger deploy gate, but if implemented naively that gate fires after `npm version` already ran — a failed gate then leaves a dangling tag in git that must be cleaned up manually. This task resolves the ordering problem definitively by pre-calculating the version and running the gate first.

---

## 🔍 Problem Statement

`scripts/deploy.ts` currently bumps the npm version (commits a git tag) BEFORE any ledger gate exists. Task 1.14 intends to add a gate, but if implemented naively it would still fire after `npm version` already ran — meaning a failed gate results in a dangling orphan version tag in git that must be manually cleaned up. The fix requires computing the target version via semver arithmetic BEFORE calling `npm version`.

---

## 📄 Key Files to Create / Modify

1. **`scripts/lib/semver-utils.ts`** *(New)*
   - `calculateTargetVersion(current: string, bump: 'patch'|'minor'|'major'|'prepatch'|'preminor'|'premajor'|'prerelease'|string): string`
     - Replicates npm's semver bump logic for all standard bump types.
     - Pure function — no npm dependency, no side effects.
   - `compareSemver(a: string, b: string): -1 | 0 | 1`
     - Pure numeric comparison of semver strings.
     - Returns `-1` if `a < b`, `0` if equal, `1` if `a > b`.
   - `isValidSemver(v: string): boolean`
     - Validates against `/^\d+\.\d+\.\d+(-[a-zA-Z0-9.-]+)?$/` (no `v` prefix allowed).
   - Export all three. These will be consumed by both `deploy.ts` and `migrationService.ts` (1.11).

2. **`scripts/deploy.ts`** *(Modify)*
   - Import `calculateTargetVersion` and `compareSemver` from `./lib/semver-utils`.
   - Add a new **Step 3.5** (positioned between the existing token audit step and the `npm version` call): **"Ledger Pre-Flight Check"**.
     - Calls `calculateTargetVersion(currentVersion, bumpType)` to compute the target version.
     - Reads `src/migrations/ledger.ts` as raw text (using `fs.readFileSync`) and parses version strings with a regex — does NOT dynamically import the module (avoids circular issues and works before the module is fully valid).
     - Regex to extract versions from ledger: `/version:\s*['"](\d+\.\d+\.\d+[^'"]*)['"]/g`
     - Confirms an entry exists for the target version with non-empty `breakingChanges` and `contentChanges` arrays (detected via regex or simple string contains logic).
     - Calls `process.exit(1)` if the entry is not found or is incomplete.
     - Prints a clear ANSI-formatted error listing: target version, what's missing, and the exact ledger format to add:
       ```
       ❌ DEPLOY BLOCKED: Missing migration ledger entry for v{targetVersion}!

       Add the following entry to src/migrations/ledger.ts BEFORE running deploy:

       {
         version: '{targetVersion}',
         releaseDate: 'YYYY-MM-DD',
         title: 'Release title',
         summary: 'Brief summary of this release.',
         breakingChanges: ['Describe breaking change here'],
         codeActions: [],
         contentChanges: [],
       }
       ```
   - The gate MUST run before `npm version` is ever called. Any existing version bump logic must be moved to after a successful gate pass.

## 🔍 Verification Criteria

- [ ] `calculateTargetVersion('0.1.3', 'patch')` returns `'0.1.4'`.
- [ ] `calculateTargetVersion('0.1.3', 'minor')` returns `'0.2.0'`.
- [ ] `calculateTargetVersion('0.1.3', 'major')` returns `'1.0.0'`.
- [ ] `isValidSemver('0.1.4')` returns `true`; `isValidSemver('v0.1.4')` returns `false`.
- [ ] Running deploy with no ledger entry for the target version aborts BEFORE `git tag` is created.
- [ ] `git tag --list` shows no new tags after a failed gate run.
- [ ] Running deploy with a valid ledger entry proceeds past the gate normally.
