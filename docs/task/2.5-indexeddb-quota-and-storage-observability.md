## 🎯 Purpose & Scope

Prevent silent loss of disaster-recovery snapshots by surfacing clear observability when IndexedDB writes fail. In private browsing modes, sandboxed iframes, or when storage quotas are exceeded, IndexedDB transactions fail silently, leaving only lightweight metadata in `localStorage` without the actual canvas ASTs or text dictionaries.

This task adds return tracking and event dispatching for IndexedDB save failures so that the coordinator receives an explicit warning toast rather than discovering missing recovery snapshots after a disaster.

---

## 🔍 Problem Statement

In `src/services/historyService.ts`:
1. `saveHistoryManifest()` persists full snapshot bundles to IndexedDB on line 309:
   ```ts
   saveToIndexedDB(STORAGE_KEY_HISTORY_MANIFEST, updated).catch(() => {});
   ```
2. The promise is fire-and-forget and errors are swallowed with an empty catch.
3. If IndexedDB fails to write (e.g. `QuotaExceededError`, `SecurityError` in Safari private mode, or corrupted database lock):
   - `saveToIndexedDB` returns `false` (or throws).
   - The coordinator receives no warning.
   - On the next session reload, `hydrateHistoryFromIndexedDB` fails and falls back to the lightweight metadata-only `localStorage` manifest (`< 50 KB`, without canvases).
   - If the coordinator attempts to restore a snapshot, it restores empty canvas trees, resulting in catastrophic loss of historical work!

## 🛠️ Step-by-Step Implementation Instructions

### Step 1: Export Event in `src/services/historyStorage.ts`

Define and dispatch:
```ts
export const EVENT_INDEXEDDB_ERROR = 'engine-indexeddb-storage-error';

export function notifyIndexedDBError(action: 'save' | 'load', error: unknown): void {
  if (typeof window === 'undefined') return;
  try {
    const errorMsg = error instanceof Error ? error.message : String(error);
    window.dispatchEvent(
      new CustomEvent(EVENT_INDEXEDDB_ERROR, {
        detail: { action, error: errorMsg, timestamp: new Date().toISOString() },
      })
    );
  } catch {
    // Non-browser context
  }
}
```
Inside `saveToIndexedDB`, call `notifyIndexedDBError('save', req.error)` on `req.onerror` and in the `catch` block.

### Step 2: Handle Result in `src/services/historyService.ts`

Update line 309 in `saveHistoryManifest`:
```ts
  saveToIndexedDB(STORAGE_KEY_HISTORY_MANIFEST, updated).then((success) => {
    if (!success) {
      console.warn('[historyService] Persistent IndexedDB backup failed. Local recovery snapshot may not persist across sessions.');
      notifyIndexedDBError('save', new Error('IndexedDB save returned false'));
    }
  }).catch((err) => {
    console.warn('[historyService] IndexedDB save exception:', err);
    notifyIndexedDBError('save', err);
  });
```

### Step 3: Wire Toast in `DeveloperModeContext.tsx`

In `src/context/DeveloperModeContext.tsx`, add an effect:
```ts
useEffect(() => {
  if (typeof window === 'undefined') return;

  const handleStorageError = () => {
    showToast(
      'Browser storage limit reached — full snapshot backup could not be saved locally. Export a JSON backup to protect your work.',
      'error'
    );
  };

  window.addEventListener(EVENT_INDEXEDDB_ERROR, handleStorageError);
  return () => window.removeEventListener(EVENT_INDEXEDDB_ERROR, handleStorageError);
}, [showToast]);
```
