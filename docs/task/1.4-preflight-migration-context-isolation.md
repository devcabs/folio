## 🎯 Purpose & Scope

Extract all migration-related state and modal lifecycle into a dedicated `MigrationContext` to prevent `DeveloperModeContext` from becoming a God Context. Task 1.12 originally planned to add migration modal state directly into `DeveloperModeContext`, but doing so increases coupling, widens the blast radius of any bug, and forces every dev-mode consumer to re-render on migration state changes. This task defines the clean context boundary before either context is fully implemented.

---

## 🔍 Problem Statement

`src/context/DeveloperModeContext.tsx` currently orchestrates: PIN security, session heartbeat, tab lock contention, draft session lifecycle, cloud hydration, undo/redo, and toast state. Task 1.12 plans to add migration modal state and pending migration checks directly into this context. Adding more state/logic to this God Context increases coupling, makes the blast radius of any bug enormous, and forces all context consumers to re-render on migration state changes.

---

## 📄 Key Files to Create / Modify

1. **`src/context/MigrationContext.tsx`** *(New)*
   - Define `MigrationContextType` interface:
     ```ts
     interface MigrationContextType {
       pendingReport: PendingMigrationReport | null;
       isMigrationModalOpen: boolean;
       openMigrationModal(): void;
       closeMigrationModal(): void;
       markAsMigrated(): void;
       generatePrompt(): string;
     }
     ```
   - `MigrationProvider` component:
     - Props: `engineConfig: EngineConfig`, optional `storage?: StorageAdapter`, `children: React.ReactNode`.
     - On mount (`useEffect` with `[]`), calls `getPendingMigrations(resolveContentWatermark(engineConfig.contentVersion, storage))` and sets `pendingReport` state.
     - `markAsMigrated()`: calls `updateWatermark(pendingReport.currentEngineVersion, storage)` then re-runs the pending migration check to refresh `pendingReport`.
     - `generatePrompt()`: delegates to `generateAiMigrationPrompt(pendingReport)` from `migrationPromptFormatter.ts` (task 1.5). Returns empty string if `pendingReport` is null.
   - **Critical constraint**: `MigrationContext.tsx` MUST NOT import anything from `DeveloperModeContext` — zero circular dependency.
   - `useMigrationContext()` hook:
     - Throws a descriptive `Error` if called outside of `MigrationProvider` (not a silent null/undefined):
       ```
       useMigrationContext must be used within a <MigrationProvider>
       ```

2. **`src/context/DeveloperModeContext.tsx`** *(Modify)*
   - Remove any direct migration state variables (`isMigrationModalOpen`, pending report state, etc.).
   - When `isDevMode` becomes `true` (PIN unlock or valid session) AND pending migrations exist, fire the action toast by calling the existing `setToastState`. The `onAction` callback calls `openMigrationModal()` obtained from `useMigrationContext()`.
   - Import `useMigrationContext` from `./MigrationContext` for the callback only.
   - Zero migration state lives in `DeveloperModeContext`.

3. **`src/App.tsx`** or the consumer mount point *(Modify)*
   - Wrap the app with `<MigrationProvider engineConfig={config}>` as a **sibling** of `DeveloperModeProvider` — not nested inside it. Order: `MigrationProvider` wraps `DeveloperModeProvider` (so dev mode can call `useMigrationContext`).

4. **`src/context/index.ts`** *(Modify or New)*
   - Export `MigrationProvider`, `useMigrationContext`, `MigrationContextType`.
